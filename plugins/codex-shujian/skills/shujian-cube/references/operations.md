# Agent 操作与排错指南

面向使用数简立方的 DeepSeek Harness、Codex 和其他控制端。根据当前任务和工具回执选择动作；下表不是必须逐项执行的流程。界面用户可在工作流中点击节点，打开“使用说明”。SFT、多轮与历史 CoT 节点还提供“输出适配”。

## 可操作范围

先从当前安装的 `capabilities` 确认动作，再查配置或记录。核心控制协议不会替外部 Agent 执行任意代码，也不支持编辑已冻结配方。

连接参数中，`--root` 是产品根目录，`--workspace` 是已登记的工作区 **ID**，不是磁盘路径；普通本机使用 `default`。DSH 的 `project` 是该插件配置中的项目 ID，也不是路径。传入绝对路径冒充 workspace 可能只得到 `control_operation_failed` 或 `core_capabilities_unavailable`，应先核对这三个含义，不能因此更换模型或反复重试。

需要把无模型验收的所有状态留在隔离目录时，准备一个独立产品根目录：复制现有 `lib`，也可将只读代码 `lib` 链接进去；两种方式都需要复制版本控制内的 `configs`，尤其是必需的 `configs/preferences.yaml`。不要复制原任务、运行状态或模型凭据。使用该独立根目录、`workspace=default` 和现有产品 Python 的显式路径；无需复制环境、权重或真实用户数据。技能安装目录和 DSH profile 也放入隔离目录。宿主 CLI 能创建 profile 不代表核心已经连接，仍以 capabilities 的真实回执为准。

| 目的 | 可用入口 | 如何判断完成 |
| --- | --- | --- |
| 找已有工作 | `runs.list` → `runs.inspect` | 找到持久 run_id、状态、节点、实际消耗；宿主临时 job_id 不是 run_id |
| 看进度 | `runs.events`、`runs.streams`、`runs.stream_delta` | 复用返回的字节游标，区分排队、流式输出、已保存结果；零增量不等于失败 |
| 找模型 | `models.list`、`models.status` | 查看已配置模型及共享并发；这里不会联网发现新模型或测试模态 |
| 改共享并发 | `models.limit` | 在上游实际限额内调整，确认新的共享状态；不要为每个节点另建并发池 |
| 新建工作 | `runs.create` | 获得冻结配方和 run_id，尚未开始生成；重试同一请求复用 request_id |
| 执行或恢复 | `runs.execute`，DSH 用 `dataforge_dispatch` 托管 | 复用 run_id 与检查点，保存执行句柄，并以持久状态确认结束 |
| 请求停止 | `runs.cancel`，结合宿主作业状态 | 取消意图、进程结束和检查点落盘是三个不同事实 |
| 查看交付 | `runs.preview`、`runs.quality` | 实际训练记录、完整推理、质量覆盖和文件核验分别查看；哈希正确不证明内容正确 |

动作参数以随包控制参考及当前 capabilities 为准。Codex 包用 `scripts/control.py` 处理 UTF-8 传输；DSH 包用原生工具。不要根据另一种 Agent 的工具名称猜本产品动作。控制协议未提供某项操作时，指出对应节点界面或产品公开 API，不能假造工具或直接改内部任务文件。

## 按症状定位，不重复付费试错

| 现象 | 先看什么／为什么可能出现 | 合理调整与验证 |
| --- | --- | --- |
| Agent 找不到工具或拒绝协议 | 宿主技能发现、插件安装回执、协议版本；安装成功不等于宿主加载成功 | 按独立包说明连接正确安装目录；先 capabilities 无模型探测。没有真实宿主加载证据就只报告本地协议可用 |
| 创建被拒绝 | `error.code`、配方字段和当前能力；可能为不支持字段、源文件缺失或配置冲突 | 只改错误涉及的字段；保留失败回执。修改请求内容后使用新 request_id；同内容断线重试使用旧 id |
| 创建结果不确定 | `control_create_outcome_unconfirmed` 或进程中断 | 找已有预留任务并核对持久状态；不能无脑新建、删除半成品或宣称成功。`control_request_id_conflict` 表示同 id 被用于不同内容 |
| 启动后看似不动 | runs.inspect、events、models.status 的 active/queued/cooldown 与最后事件时间 | 排队先等共享资源；认证、限流、额度错误按回执处理。不要重复 execute 或重跑已完成节点；额度不足由用户处理上游账户 |
| 输出半截／格式失败 | 完整请求收据、finish_reason、流最后状态、上下文和输出上限 | 区分传输中断、截断、协议拒绝与内容缺陷。节点配置合适上限与协议，保留原始响应；别靠删除推理或猜 JSON 字段补成成功 |
| 参数调整没有改变旧任务 | 检查配方冻结时间与节点绑定 | 草稿只影响随后创建的任务。需新配置时复用任务另建工作，保留旧记录；恢复旧任务继续使用其冻结版本 |
| 解析内容缺页／表格单位丢失 | 页码、原文、图表局部图、解析器状态、模型已验证模态 | 输入解析节点选择已安装解析器，必要时启用经过验证的多模态辅助。复用完整缓存；配置改变需要生成新解析版本，不覆盖原始资料 |
| RAG 命中短且无上下文 | 检索命中、行范围、邻接段、图表说明与单位 | 调整知识库范围、相关条目与上下文容量；缺证据就待补充。向量用于找文字，不是直接注入模型的思考指令 |
| 新问答很重复或角色失真 | 指导员计划、用户说话方式、逐轮角色、问题与资料范围 | 在指导员节点改场景与提示词；在生成节点确认完整历史和材料。新生成问答需要指导员；不要用固定长短或给每句加序号来伪造多样性 |
| 导入 DSH 会话没有推理 | 原始消息是否含 reasoning、导入节点的缺失推理选项 | 保留缺失状态，或按用户选择补写。补写是合成推理，不是找回原生思考；答案无法证实时保留待完善，不能硬编理由 |
| 自动分数高但内容仍错 | 完整用户要求、每轮助手答复、资料条件、评审证据和版本 | 区分原稿缺陷、证据不足与误判；不要把历史助手的话当事实。只对已确认问题使用返工分支，保留父子版本，不增加无授权无限评审 |
| 推理出现控制参数文字 | 先判定是上游原生内容、自身模板、可见用户原话还是内部记录 | 若是稳定的字面控制段，在输出适配中标记或替换；语义泄漏用提示词/修剪/返工处理。不能因为重复出现就断言上游训练方式 |
| 配置替换后报告仍有原字样 | 原始记录与训练读取视图不同 | 本功能保留原推理；查看节点本地预览或训练加载器的适配结果。关闭总开关可逐字保留控制文字，记录仍可审计 |
| 规则未命中／误命中 | 节点归属、开头范围、开关、实际原文、别名、marker、任务引用 | v3 只处理开头范围内的完整匹配，正文同词保持原样。精确匹配不会泛化到未知拼法；可查看已有评审提出的别名建议，核对含义与预览后保存，不必为此重新生成 |
| 规则冲突无法保存 | 重复 id、重叠 marker、替换形成级联、空匹配内容或无效标签名 | 在“输出适配”的编辑区修正并预览，或取消修改。未保存输入不替换已生效配置；旧草稿已有冲突时仍须修复，不能跳过启动校验 |
| 成对标签不完整 | 开头范围内的实际推理是否已被外部截断、嵌套或改过标签 | 保留原文，回到完整记录修复标记结构后预览；不要补写未知内容或删除后续推理。正文范围外的同名标签不参与本功能，错误也不代表模型质量通过 |
| 评审没有提出新规则 | 节点的评审建议开关、是否实际执行评审、已有别名、候选前缀和建议回执 | 空建议可以是正常结果。未启用、未执行或未使用建议协议不能算已发现新规则；不为获取建议追加一次付费评审 |
| 建议无法采用／规则已变 | 原句出处、候选与配置版本、当前节点配置 | 只有证据有效的建议可进入待确认列表。配置发生变化时先重新核对，不覆盖新设置；字面出处正确仍不证明两种措辞语义相同 |
| 导出隔离／下载失败 | 质量报告、来源与哈希、审核发布版本、返工父子关系 | 处理真实原因，选择经过核验的发布产物。未抽检不算评审通过，返工父子不算两个独立合格样本 |

回执没有变化、也没有新的故障依据时，等待或报告阻塞；不要反复探测收费模型。修改一次后优先做可定位的本地预览或小范围验证，再按授权恢复真实任务。判断不清的语义问题保留为待复核。

## 技术开关的作用范围

### 原生推理、强度与篇幅

新 SFT / 多轮的原生模式由回答模型同时输出推理和答案；历史正文 CoT 是不同路径。原生推理是否存在由上游协议与能力决定。思考强度保存为平台的 low–max，运行时再映射上游；上下文上限、单次输出上限与思考强度不是同一参数。不要将观察到的 `verbosity 5` 推断为 max，也不要假定每个上游支持全部档位。

Qwen3.5 训练示例的思考开关是目标模型预处理映射，默认五档均开启，可按训练者选择让 low 关闭。该映射不重写数据集，也不改变已有任务的上游调用配置。

### 节点控制文字适配

入口：点击 SFT / 多轮 / 历史 CoT 节点 → 输出适配。默认只读，点击编辑后调整总开关、单条开关、匹配文字、开头范围、包裹标签、回执标识和目标文字，并做免费本地预览。通过校验后明确保存才生效；取消修改或保存失败均保留原配置。上一版和默认规则可先载入编辑区，预览后再保存，不会一点击就覆盖。总开关关闭保留规则，单条关闭不影响其他规则。

新配置采用 `shujian.control-text-adaptation/v3`，`annotation_tag` 默认是 `reason-strength`。**仅标记把原控制文字放在成对标签内**，例如 `<reason-strength>Desired oververbosity 5</reason-strength>`；不把原词句换成占位符。回执 `source_control_annotations` 继续记录命中范围、原文、规则 ID 和回执标识。启用该版本的新任务导出提供带标签的推理视图，源候选与完整原生响应不变。重复读取不重复包裹。

`prefix_char_limit` 默认是 512，节点可设为 64–2048 个原文字符。只处理完整落在该范围内的控制片段，正文中的相同字句保持原样。已识别的包装标签不消耗原文字数；完整标记块跨越边界时整块保留。范围控制用于避免误触正文，不是限制模型的思考或答案长度。

普通导出只标记；只有训练加载时明确配置 `replacement`，才把控制片段替换成目标文字。标签名可在节点上改为其他简单名称，总开关或单条开关可关闭；关闭时保留原文及已有标签。标签不删除推理，也不触发模型调用。`reason-strength` 只是定位名称，不能将 verbosity 5 推断成 low–max；实际档位仍以 `training_control` 为准。

配方字段是 `node_control_text_configs`，键为 `sft`、`multiturn`、`cot`；v3 每项有 `schema`、`enabled`、`annotation_tag`、`prefix_char_limit`、`review_suggestions` 与 `rules`。规则包含 `id`、`enabled`、`matches`（完整字面列表）、`marker`、`replacement`（null 表示仅标记）。程序只做精确匹配，不执行用户正则或代码。旧 v1 保留占位符转换，v2 仍只存旁路标注、不加内联标签。界面编辑会准备 v3 配置，只有保存后才用于新任务；既有冻结任务不热迁移。

下面是供 Agent 组装配方的字段片段；`schema` 必填。它不是完整生成配方，也不要求界面用户手写 JSON。

```json
{
  "node_control_text_configs": {
    "sft": {
      "schema": "shujian.control-text-adaptation/v3",
      "enabled": true,
      "annotation_tag": "reason-strength",
      "prefix_char_limit": 512,
      "review_suggestions": true,
      "rules": [{
        "id": "deepseek-output-verbosity-5", "enabled": true,
        "matches": ["Desired oververbosity 5", "desired verbosity 5"],
        "marker": "[[SJ_OUTPUT_VERBOSITY:5]]", "replacement": null
      }]
    }
  }
}
```

原生训练记录携带 `control_text_node` 与 `control_text_config` 快照。训练加载器按记录应用，调用者显式配置优先；旧记录没有配置时保留既有兼容行为。当前任务没有配置的节点不会凭空启用一套规则。原生 SFT 的 CoT 投影继承 SFT 规则，避免被误认为另一个 CoT 作者。关总开关只关闭文字适配，不关闭模型思考或其他质量检查。

原始推理、完整响应、缓存和已冻结配方不被 UI 编辑覆盖。默认 DeepSeek 字面仅表示已观察到的稳定字符串；回执标识与成对标签供定位和目标模型加载时映射，不代表可以推知供应商私有配置。`Desired oververbosity 5` 不应误匹配 50、5.0 或 5e3。

### 让现有评审提出规则建议

`review_suggestions: true` 允许已有评审在同一次调用中查看作者节点的冻结规则和实际推理前缀，并提出相似写法。新默认开启；缺少这个字段的配置按关闭处理，旧任务不会自动升级。节点上可关闭建议功能。没有执行评审时不另起模型请求；新增的规则上下文仍计入该次评审的实际 token 消耗。

建议只可向已有、已启用且 `replacement: null` 的规则增补精确原句。每项建议绑定候选、来源消息、原文位置和规则版本；程序核对它确实位于开头范围，且不是用户任务中引用的同一片段。模型不能借建议改替换目标、标签名、前缀上限、开关或质量标准。建议失败或缺失不触发额外付费重试，原质量响应仍按原协议校验。

有效建议先持久保存为待确认，在节点内查看原句、理由和标记前后差异。确认语义确为同一个控制字段后再载入规则草稿，保存才用于新任务；取消或恢复上一版仍可用。配置已变化时不能用旧建议覆盖。**出处已核验不等于含义已认证，提出或采用建议也不等于样本评审通过。** 不要直接编辑内部任务文件或为采用建议修改运行中、已冻结任务。

### 评分、修剪与经验

评分与修正属于同一质量节点的不同职责；使用 JEV 时可分别指定评分与修正模型。不使用 JEV 时可由同一模型承担。无独立评审的生成可以继续成为候选，但不能标成已评审通过。

修剪用于用户选定的输出调整，保留原稿；精确控制文字适配不替代语义修剪。新经验可增量更新并用于新任务，也可尝试修复相关旧失败；不得热改运行中任务、强求每条通过或无限自动回流。

## 向用户交付哪些证据

至少给出任务身份、当前状态、所改节点及配置版本、仍存在的问题。发生模型调用时给出实际请求次数、耗时和返回 usage，金额只能按已知价格估算并注明口径；离线修复就明确没有新 API 消耗。展示完整问答与保留的推理，并区分原始内容、训练视图变换、审核覆盖、人工观察和已验证结果。

这份指南在独立包中以 `references/operations.md` 随包分发。仓库 `docs/agent-operations.md` 是维护源；更新接入包后使用全新、无上下文测试者验证，并保留包摘要与真实回执。安装、协议调用、原生宿主工具加载和业务完成分别报告。

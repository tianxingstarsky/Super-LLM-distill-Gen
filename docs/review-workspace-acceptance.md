# 固定人工审核工作台：实现与验收

## 本次变更

旧审核页是纵向表单：配置、样本导入、下拉选样、完整会话、AI 面板、判定依次排列。两条短消息时，判定提交按钮已位于约 1171px（1100px 视口外）；编辑一条会将全会话解除 Markdown 渲染。

现改为 Streamlit components.v2 内的固定工作面：

- 左侧摘要队列：搜索、待我审核/我已审核/全部、分页；只查询摘要，选中后读取一条完整记录。
- 中间独立滚动阅读区：默认 Markdown，消息目录定位；仅当前字段进入源码编辑，其他消息保持渲染。工具结果完整展示，不套用预览截断。
- 右侧判定区：理由、主动选择的理由模板、保留/驳回并下一条、跳过。不默认选择保留，不替用户填写审核依据。
- 局部 AI 修改：消息旁输入要求，看建议后采用或手动调整；不再在会话底部重复展示全对话。G0/G1 未批准不调用模型。
- 草稿切换保护；保存成功回渲染态并保留正文滚动位置。保存期间禁用输入，避免新输入被已发出的保存回执覆盖。草稿绑定打开时的 record_id/hash，不被后续刷新静默重绑定。
- 导入和身份/Agent 接入配置移出日常审核面。个人身份使用中心已有密钥验证，队列和状态按 workspace/dataset/username 隔离。
- 本机管理员入口仍为可信本机操作入口，不是可公开部署的多人登录站点；远程协作继续使用已有认证 API/各自主机 Agent。

## 主题

统一 `.streamlit/config.toml`、`console_theme.DARK_TOKENS` 和工作面颜色。控制台嵌入 `MESSAGE_CSS`，不再注入带全局 body/root 的独立 HTML 样式。正文、编辑文字、原生输入、占位文字及浮层有显式深色配色。

本次代码确认存在强制暗背景与各层自行选择主题的冲突，但代理能访问的内置浏览器本身处于 dark 偏好，最初没有复现用户具体浏览器的黑字。不能把该浏览器通过当作用户所有浏览器已验收。普通文字颜色对比测试 >=4.5:1；编辑框实测浅色文字 rgb(249,250,251)、背景 rgb(18,29,44)。

## 后端安全与可靠性

- `queue_page` / `queue_position` / `get_record` 统一校验 dataset 权限，查询仅匹配该审核者自己的审核票。
- `revise_field` 在事务内校验版本、分配修订号、保存完整样本，并记录幂等请求回执。原始记录不覆盖，消息角色、图片、工具元数据不变。
- `submit` 保留审核票唯一性和内容哈希检查。已审核页不允许再次覆盖判定；没有删除审计票的“撤销”。
- 图片引用只读；远程图片不自动请求。本地图片只允许工作区源目录内、无链接/junction/目录穿越的有界 PNG/JPEG/GIF/WebP。无法显示时明确提示未查看。
- Markdown 原始 HTML 转义，图片与链接另做安全处理；失败时退化到转义纯文本。
- 修复 Streamlit 1.63 程序化启动陷阱：`bootstrap.run` 不应用首次 flags，必须先 `bootstrap.load_config_options`。最终实际监听为同一进程的 `127.0.0.1:8501` 与 `127.0.0.1:6900`，不暴露可信本机管理员界面到所有网卡。
- 关闭 Streamlit 文件监听；没有新增 watchdog、Node 运行服务或弹窗启动。源码更新后需明确重启本项目控制台。

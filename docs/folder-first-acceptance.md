# 已有文件夹工作区验收（2026-09-11）

## 交付范围

- 工作区由用户已经准备好的目录注册；不再创建空的源工作区。
- CLI：`workspace add <已有路径>`、`list`、`use <标识>`、`status --ws <标识>`。
- 控制台：打开文件夹、最近打开、源文件清点、实际产物路径；选区仅限浏览器会话。
- 导入、蒸馏和默认翻译输入跟随选定文件夹；产物写到 `.dataforge/output/`。历史默认路径与旧工作区保留。
- 文件扫描排除产物目录、依赖目录、符号链接及 Windows junction；递归统计按相对路径区分同名文件。
- 默认 Markdown 阅读；按消息进入源码态，保存为独立版本，取消回到阅读态。重复渲染不会覆盖草稿。
- 修订保留完整样本元数据；结构化消息内容只读，不能静默压成字符串。并发保存由 SQLite 事务分配独立版本号。

## 自动化验证

在项目 Python 3.11 虚拟环境中，测试临时目录与模型/包缓存均指向 F 盘。

```bash
python -m pytest tests/ -q
# 188 passed
python -m pytest ui_tests/ -q
# 7 passed
```

两个套件使用独立进程，避免 Streamlit AppTest 与 distilabel multiprocessing 混用。
主套件包含源文件只读、目录失联、注册并发、跨区状态、Windows junction、修订元数据、版本并发、编辑组件事件和草稿保留测试。
依赖仍有 distilabel/Pydantic 弃用警告；本轮未升级依赖。

## 实际浏览器流程

使用独立合成验收数据，不使用或上传用户真实聊天数据：

1. 提前准备包含 `dialogues.jsonl` 的文件夹。
2. 在“打开已有文件夹”弹窗粘贴目录并提交。
3. 侧栏切换至新目录；该目录的待审队列为空，不混入 default 的旧记录。
4. 加入合成样本后，标题、粗体、列表、代码块和思考内容按 Markdown 渲染。
5. 点击助手消息编辑，正文显示 Markdown 源码；输入验收标记，保存生成 `folder-acceptance-1-r1`。
6. 保存后恢复 Markdown 阅读，标记以粗体显示。
7. 对本地源文件及审核数据库进行核对：原文件无验收标记，原样本消息未变，新版本内容哈希不同；打开和审核没有创建 `.dataforge/output/`。
8. 持久化当前工作区仍为 `default`，浏览器选择未改写 CLI 默认值。

浏览器完成了路径输入、编辑输入及保存的实际界面流程；按钮自动化存在定位超时，使用同一页面可交互节点/按钮事件回退后验证结果。未将仅派发成功当作保存成功。

## 边界

- 本轮未调用付费模型、未跑新的 DSH 子智能体任务，AI 修订范围由离线回归覆盖。
- 本轮实际验证了粘贴路径方式；系统原生目录选择器没有纳入浏览器自动化。
- 多模态结构化内容保持只读，不宣称本轮实现图像部分的可视化编辑。
- 工作区注册表、审核数据库、模型密钥、本地配置和验收数据不提交；OpenCUA 既有子模块修改保持原状。
- 控制台仍采用单实例、无窗口启动，没有新增看门狗或自动重启循环；仅刷新本项目控制台，未操作用户训练进程。

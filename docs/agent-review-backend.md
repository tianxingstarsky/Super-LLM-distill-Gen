# Agent trace review backend

This is a local, single-workspace backend slice. It is not connected to the Streamlit review page. It has no Agent release or download method. The reviewer name is supplied by the caller and is not an authenticated identity. Do not use this adapter for team workspaces or as a permission boundary. Team integration requires authenticated actors and parent-handle confinement of the output root, including symlinks and Windows reparse points.

The backend indexes `agent.jsonl`, `agent.records.json`, and `agent.negative.jsonl` together. Eligible native rows and their records form the positive queue. Failed trajectories form a separate, read-only negative queue. A negative candidate cannot receive a review decision. The backend does not send either queue to training.

For an unpruned arithmetic-tool trace, the backend independently runs the recorded messages through the local deterministic replay assessor. It compares the resulting messages and full verification record with the sidecar. Only such a candidate can be approved. A trace that uses a snapshot, a container, or pruned calls remains visible for inspection but cannot be approved by this backend. These cases need a future verifier with independently anchored inputs. The sidecar's original-message hash and source manifest are stored in the same writable run; they are not independent proof of the original input before indexing.

Each decision binds the run ID, manifest hash, all three artifact hashes, native row hash, sidecar row hash, and expected review version. A source change after indexing invalidates that run's review store. The caller must start a new run to review changed evidence. Decisions are append-only with an eight-version limit per candidate and a 100,000-event limit per run. The decision log is an input for a future release gate, not a publishable training artifact.

The initial index streams source rows into SQLite. Queue reads return at most 20 candidates; offsets are limited to 50,000. A native JSONL line is capped at 4 MiB. An individual sidecar object is capped at 2,097,152 characters and 8 MiB of UTF-8 text. Source hashes are rechecked on each queue and decision call. This can make repeated pages of a large run slow; a modification-time-only cache would weaken invalidation. The backend does not run training or claim that Agent human review is available in the UI.

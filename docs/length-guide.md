# 训练数据长度策略（上限守卫，非目标约束）

## 核心原则（用户确认）

- **长度是"上限保护"，不是"生成目标"**：解决问题操作越少、无用输出越少越好，
  不做工程化注水式长数据。
- **长数据靠任务性质自然长**，三个天然来源：
  1. **真实 agent 长对话**（rollout 蒸馏）：你的真实会话就是最好的长上下文数据，
     单样本 65 条消息/数万 token，多会话拼接即百万级——有多少用多少；
  2. **知识学习任务**（文档/文章/代码综合分析）：`df doc2data --mode cross`
     生成需通读多块才能回答的对比/归纳/综述问答，答案天然长且质量可靠；
  3. **多步轨迹**（agent-gen / gui-cot）：多跳任务自带长程因果链。
- **不绕弯子**是配套守卫：agent 轨迹冗余修剪（同名同参重复调用直接剪掉）、
  质检判冗余调用 invalid、GUI 轨迹按上游 efficiency_score 过滤。

## 配置（configs/pipelines/length_profiles.yaml）

```yaml
max_context:
  answer_tokens: 16000   # 单条回答截断上限（保护性；0=不限）
  sample_tokens: 64000   # 单样本（多轮拼接后）截断上限（0=不限）
```

`df identity-gen --max-answer-tokens N` 可单次覆盖；其余生成命令同构。
截断只是护栏——数据本身多长由任务决定。

## 长数据怎么配比

- 通用助手：短中长自然混合（真实用户提问本来就是混合的），不需要强制；
- 长程 agent：rollout 真实长对话为主 + `doc2data --mode cross` 知识综合 +
  agent-gen 多跳轨迹为补充；
- 百万上下文：仅来自真实长对话拼接（df import 的会话数据），合成侧不做此尝试
  （单次输出上限 + 多轮拼接质量衰减，见 docs/length-guide 历史版本的诚实说明）。

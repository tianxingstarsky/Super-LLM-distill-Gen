# 训练数据长度控制指南

## 目标长度怎么设

生成类命令通过 `--length` 指定（以 identity-gen 为示范，其余生成命令同构）：
`short(200) / medium(800) / long(3000) / xlong(8000) / mixed(按配比混合)`，
配比在 `configs/pipelines/length_profiles.yaml` 可调。长度要求注入到生成提示词的
风格要求里（追加式，不改提示词结构）。

## 诚实边界：合成数据的长度上限

| 长度量级 | 来源 | 可行性 |
|---|---|---|
| 数百~数千 token | 单次合成生成 | ✅ 可靠（模型单次输出上限内） |
| 数万 token | 多轮拼接/续写 | ⚠️ 可行但质量随轮次衰减，需逐段质检 |
| 百万上下文级 | **真实 agent 长对话** | ✅ 只有这一条路：rollout 蒸馏（你的真实会话，单样本 65 条消息/数万 token，多会话拼接可达百万） |

**为什么合成做不到百万级**：模型单次输出有上限（数千 token）；靠反复续写堆到百万，
信息密度与一致性会崩，且合成内容没有真实任务的长程因果链——这正是用户真实与
智能体工作产生的对话才有的东西。所以方案是分工：
- **合成管线管"短中长"**（受控长度、质量可靠）；
- **rollout 蒸馏管"超长"**（真实轨迹，天然覆盖长程工作）；
- manifest 层合并，二者互不重复。

## 建议配比（参考）

- 通用助手：short 30% / medium 40% / long 20% / xlong 10%（mixed 默认即此）；
- 长程 agent 训练：在 mixed 之上叠加 rollout 真实长对话（df import 产物），
  比例按你的真实数据量决定——真实长对话是稀缺资产，有多少用多少。

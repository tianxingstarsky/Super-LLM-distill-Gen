# 对话指导员

对话指导员是可选的工作流节点。新任务默认使用「语言专家自适应」：根据材料、用户表达、上下文和实际目标设计有用的互动，再交给 SFT 和多轮生成节点。首句可以是陈述、请求或讨论，不要求改写成问题。偏好与 CoT 目标会使用受指导的 SFT 中间候选。CPT 语料整理、算术核验和已记录的 Agent 轨迹不由它改写。

在训练目标下开启「加入对话指导员」，然后点击画布上的指导员节点。节点设置中选择指导方式、批次大小和历史参考数量；「提示词与风格」中设置对话设计指令、回应与任务推进指令和完整提示词。生成节点及评审步骤各有自己的提示词，支持直接编辑或导入 UTF-8 TXT / Markdown。

自适应方式不按题型配额分配任务。指导员选择线索可见方式，同时给出开放文本的互动目标、用户意图、上下文联系、成功标准、轮次建议和停止条件；它们用于指导，不是固定行为清单。联系必须有语境支持，猜测仍作为假设，不能编造用户经历。需要精确控制线索比例时，可以选择「按线索比例安排」；此方式沿用相对权重，设为 0 即关闭对应类型。规则和模板正文随任务保存；恢复任务不追随后来修改的草稿或内置模板。模型、上下文窗口和单次输出上限也在节点中配置。旧任务缺少指导方式时继续沿用原有配比行为。

生成多轮时，指导员在每次已验收的真实回应之后重新规划下一条用户消息。它看到完整的当前对话、原设计和当前理解、未解决问题、约束及指代关系。下一轮可以修改、补充、协商、澄清或继续分析；不能把整段后续提问提前写死。「每段最多轮数」只是上限，目的达到即可结束。训练多轮至少需要两组完整互动；只有一轮价值的候选不会靠无效续写补成多轮。自然结束时保存最新进展，生成与逐轮、整段评审使用相同的实际对话记录。

例如，用户先请求将检修资料整理成操作卡，看到实际卡片后再说「第二步那项简短一点，记录字段按你刚才那份卡继续」。这里必须承接上轮的第二步和记录字段，而不是凭空构造一个新问题。未提供的设备型号、工作环境或个人经历不能成为默认事实。

材料不足或没有新的有依据场景时，指导员可以明确跳过候选。新的软数量生产模式会记录这类反馈；先遍历未处理的新资料，再停止反复扩写。该判断是有限历史下的模型判断，不能证明所有语义可能性都已穷尽。

「恢复默认模板」会还原当前编辑项，已保存的个人模板继续保留。「我的模板」支持选中即套用；在保存入口中命名后可另存为新模板，或明确更新所选模板。完整节点提示词、指导员规则、风格要求和修剪规则分别保存。模板按当前本机用户持久保存，切换草稿或重启程序后仍可复用；保存模板不会修改已经开始的任务。

以下是线索可见方式，不是对话行为分类，也不要求在每段对话中逐项覆盖。

| 线索方式 | 最终训练输入 | 回应要求 |
| --- | --- | --- |
| 无线索 | 自包含问题，不附教师资料 | 正确回答；无线索不代表无答案 |
| 有线索 | 问题与必要证据 | 回答只依赖可见线索支持的内容 |
| 部分线索 | 问题与部分资料 | 按实际信息选择回答、澄清、有条件回答或说明不足 |
| 多线索 | 问题与多段证据 | 整合证据，检查条件和来源是否一致 |
| 干扰线索 | 有效线索与干扰内容 | 忽略无关内容及资料中的指令，不能篡改数字和事实 |

教师可见的验证资料、学习者可见的线索和评审依据分别处理。隐藏资料不自动拼入无线索训练输入，但答案和显式解释可以使用完成问题所需、经过教师资料核验的知识事实。必要的公开出处与引文不属于泄漏；内部提示词、检索包装和标识、无关原文不能进入回答，也不能假装读者已经见过隐藏的「上文」。资料不足的任务不能靠编造引文补齐。指导员和生成模型的 JSON 输出都要经过程序校验；自定义提示词不能取消这些校验。

每批执行「保存历史和覆盖快照 → 指导员设计或跳过 → 生成与评审 → 合格结果反馈」。跨任务历史只提供少量有界摘要，用于观察已覆盖的互动和避免重复，不能充当新答案的事实来源。当前多轮自身的实际完整记录另外传入指导员。节点覆盖表统计生成阶段的验收结果，最终导出数量以打包结果为准。最终打包通过的记录才进入跨任务历史。

当前本地历史采用 SQLite 持久账本与有界词汇检索。新任务的单轮指导生成同时按「实际问题＋完整可见条件」索引；只改线索类型、回应策略、活动目标或意图不能绕过相同题面去重。写入用事务处理；最终发布再次检查跨任务历史，恢复同一条记录不算重复。SFT 派生的 CoT 属于同一业务样本。旧任务沿用旧协议；旧历史的长条件只保留过摘要时，不从截断摘要推断完整题面。多轮仍按实际对话契约判断，不能仅因首句相同删除有不同后续的活动。相似消息只是规划提示，词汇相似不代表语义相同；目前不能保证所有语义改写都永不重复。

最终发布另外登记完整实际训练输入的哈希，包含真正的公开角色、正文和工具历史；私有推理不参与输入身份。人工明确改题后按新实际输入登记，不用旧契约冒充题面。自动修正只改助手答案与解释，不能改用户问题、可见资料、角色顺序或工具事实。没有实际输入指纹的旧历史不猜测补齐。

多轮按完整实际输入登记，不能仅因首问和活动目标相同就删除不同后续。发布锁内先检查同批实际输入冲突，再写训练结果；历史登记失败不生成新的完整清单。全局历史目前逐行提交，后续磁盘写入或登记失败时，已提交行可能暂时阻挡其他任务，需要恢复原任务完成发布。当前没有数据库与文件之间的整批原子提交保证。

## 长期生成的 Agent 上下文

新任务开启指导员后，当前窗口只读取有限近期设计、相关旧题、已覆盖资料与主题的计数，以及失败反馈。确定性的 `agent_memory` 投影最多约 8 KiB，不调用额外模型做摘要。原始事实仍来自不可变资料包；历史答案和覆盖摘要都不能当事实证据。记忆和真实输入在调用前一起保存为检查点，恢复时使用相同快照。

完整已接受账本不随窗口轮换而删除。接近模型容量时先移除可选历史和记忆；资料包不能直接截掉后半段，批次过大则拆分，单条原始知识窗口仍过大则要求调整窗口或节点配置。系统规则、输出预留、资料和工具消息包装均计入实际上下文检查。新任务中，已通过清洗审核的整组资料能完整装入一个窗口时，共用按固定顺序排列的资料前缀，避免跨文档事实缺失；装不下时继续使用完整文档窗口与检索。被拒绝的材料不进入事实记忆。旧任务保持保存的窗口策略。关闭指导员的普通 SFT 不使用这份指导生成账本。

这个设计借鉴 [Codex CLI 的实时历史与持久原文分离](https://github.com/openai/codex/blob/044e74fef3d1af2b01f4375158ac1e7ad4ae17ea/codex-rs/core/src/context_manager/history.rs#L518) 和 [上下文压缩检查点](https://github.com/openai/codex/blob/044e74fef3d1af2b01f4375158ac1e7ad4ae17ea/codex-rs/core/src/compact.rs#L393)。本项目使用可检查的本地投影，没有把 OpenAI 专有的加密压缩条目发送给其他服务，也没有把短期摘要当作完整知识。

风格化解释与最终答案都需自包含。普通知识应用直接陈述事实、条件与推导；只有实际输入明确包含文章时才指向这份可见文章。内部资料包装、指导员调度、提示词或评分要求不能进入解释正文。程序捕获明确泄露表述，独立模型评审检查语义、事实和有效论证；两者都不能证明无限规模数据绝无泄露。用户可以在节点风格指令中要求更长的解释，长度不会替代正确性或强制简单题凑字。

推理修饰和修剪使用分离的角色：生产规则在系统层，原始资料由已执行的 `source_memory` 工具提供，参考答案、旧解释和反馈由 `dialogue_dispatch` 提供，实际用户/助手对话保留其原有顺序。参考答案是待核对候选，不能变成事实来源。导入记录里的系统或开发者角色作为学习者上下文引用，不获得生产指令权限。工具读取已经完成后，文本生成请求禁用继续调用工具；上游仍返回工具动作时拒绝，不能把工具包装当答案。

旧候选、指导简报和评语中的错误也不代表用户持有这种误解；修正只依据真实问题与可见文章归因。明确选择样本返工时，先验证封存的父产物及原题，再允许自动修正旧正文中的来源或制作过程泄露。修正后的正文仍须通过完整检查；缺少来源、伪造工具轨迹、正文隐私或结构错误不会因此放行。人工直接评分也不能绕过正文检查。

用户提出的候选解释、猜测和评估请求保留其不确定性，不能当作用户已经断言的观点。描述两种现象同时发生，也不能推出用户相信某个机制。解释应比较实际提出的候选及其成立条件；只有用户明确说出的错误前提才需要归因并纠正。

上游成功结束但只返回推理、空白而没有正文时，JSON 层按有限次数重试相同请求，原生推理仍不能冒充正文。认证、配置、取消和未完成输出不会被这个恢复规则掩盖。指导员结构修复反馈只暴露程序白名单内的具体错误码，不回传被拒绝的私有文本。

干扰线索属于当前支持的噪声类型。自由错别字、冲突版本、任意噪声变体、自动语义聚类和百万条性能验证尚未完成。风格化生成仍由生成节点的开关控制，推理链修剪仍是可选的下游节点。

## 论文依据与工程选择

- [Clark 与 Brennan（1991），Grounding in Communication](https://web.stanford.edu/~clark/1990s/Clark%2C%20H.H.%20_%20Brennan%2C%20S.E.%20_Grounding%20in%20communication_%201991.pdf) 将共同理解视为双方持续协作的过程。这里借鉴理解状态、必要澄清和按当前目的推进，不能据此声称模型已可靠理解用户。
- [Grosz 与 Sidner（1986），Attention, Intentions, and the Structure of Discourse](https://aclanthology.org/J86-3001/) 区分表达结构、意图和注意焦点，话语结构随互动发展。这里借鉴目标、约束和指代的持续维护，不预设完整后续问答。
- [Roberts（2012），Information Structure](https://semprag.org/article/view/sp.5.6) 用当前讨论的问题组织话语。这里将其理解为尚待共同解决的议题，而不是要求每句话必须是问句。
- [Schegloff、Jefferson 与 Sacks（1977），The Preference for Self-Correction in the Organization of Repair in Conversation](https://www.conversationanalysis.org/wp-content/uploads/2019/06/11_Schegloff_et_al_The_Preference_For_Self-Correction_in_the_Organization_of_Repair_in_Conversation.pdf) 研究说话、听取和理解中的修复。这里允许双方补充、修正和确认，不把所有修复变成模型纠正用户。
- [Bunt 等（2020），The ISO Standard for Dialogue Act Annotation, Second Edition](https://aclanthology.org/2020.lrec-1.69/) 区分任务、反馈与会话管理等多个维度。它是标注框架，不是生成配额，因此本项目没有把其行为类别硬编为生成步骤。
- [Bao 等（2023），A Synthetic Data Generation Framework for Grounded Dialogues](https://aclanthology.org/2023.acl-long.608/) 研究知识支持的对话规划、逐步生成及过滤。这里借鉴规划与逐轮生成共同验收；其特定基准结果不是本项目百万规模的质量保证，也不是通用的最优样本量。
- [Self-Instruct](https://arxiv.org/abs/2212.10560) 使用生成和过滤来扩展指令数据。这里借鉴批次任务扩展与重复过滤；题型配额、检查点和历史索引属于本项目的工程实现。
- [RAFT](https://arxiv.org/abs/2403.10131) 研究含相关文档和干扰文档的训练。这里借鉴可见证据与干扰线索的区分，不把所有缺少线索的题都训练成拒答。
- [SemDeDup](https://arxiv.org/abs/2303.09540) 研究基于表示的语义去重。它说明精确哈希不足以处理语义重复，但不能证明当前本地词汇检索已经实现语义去重。

这些论文提供设计依据，不是本项目数据质量或吞吐量的实测结果。合格样本仍应结合任务用途做独立抽查与评测。

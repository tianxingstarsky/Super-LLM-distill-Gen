# 按对话风格使用上下文

上下文按交流方式组织，不按行业、学科或知识主题分类，也不是给用户设定永久人设。

| 类型 | 当前交流的特点 |
| --- | --- |
| 通用 | 各类交流共用的角色与依据边界 |
| 直接表达 | 直接提问、指令或明确诉求 |
| 情境叙述 | 通过经历、背景或处境表达需要 |
| 探索讨论 | 试探想法、联想或尚未成形的目标 |
| 协作推进 | 承接前文、反馈、纠正或推进工作 |
| 情绪交流 | 表达感受、关系需要或希望被理解 |

类型可以组合，同一个用户可以随交流变化。不规定问题或答案的长短、句式和思考步骤。

## 使用

在对话指导员节点设置中打开“按对话风格调用上下文”，可查看目录。新建原生 SFT、多轮或原生 CoT 任务会冻结目录；关闭后保持原路径。已有任务不会因开关或新经验而热改。

指导员在原有批量规划和续轮调用中选择 `dialogue_contexts`，先读取简短目录卡片。下一轮没有选择时回到通用上下文，不继承上一轮的标签。可选标签格式异常时使用通用上下文并保留原始响应及诊断，不为标签重新购买规划；问题、证据、角色和质量校验保持不变。

无线索发言者只收到选中风格的简短说明，不接收回答者正文、未选中的上下文或教师事实。原生回答者只加载通用与本轮选中的正文。真实消息、原生推理和上下文来源收据保留；上下文是交流建议，不是用户事实或合格证明。

## 已学习经验

Google 宿主提炼指导 1.1 在原来的同一次提炼中为完整经验条目标注交流类型，不增加分类模型调用。未标注的旧经验视为通用，不按题目内容猜测行业类别，也不批量重写原记录。

新任务创建时，通过现有本地嵌入和原版检索，为通用及各风格目录准备已采用的原生推理经验。先按经验来源的类型与采用版本过滤，再排序；查询用交流方式说明，不用任务名、论文主题或行业。正文、来源和容量省略记录都随目录冻结。只有本轮选中的目录正文进入实际原生请求，不在每轮重新读取当前全局采用状态。

如果个人基础文本逐字等于当前已采用的 Google 经验，程序会将这份受管理经验分配到通用／风格包，并保留精确来源及基础投影收据，避免完整经验又从常驻前缀重复进入。不同的手工编辑内容仍保留，不做模糊匹配或自动删改。新增分类与检索只证明路由和来源接线，不能证明模型已学会通用规律。

程序创建入口也可显式传入 `dialogue_style_contexts=True`。程序调用默认保留旧行为；页面创建默认启用此选项。该能力首先接入原生回答，旧正文生成、CPT 清洗及单独返工不会被暗中改成另一条流程。

同题重答保留原问题、资料范围、合同与所选风格 ID，复用父版的初始目录，并为新任务重新冻结当前采用经验；不重新调用指导员。父任务中的旧上下文与完整原生推理仍保留，重答不热改父任务。

## 维护入口

- 初始正文：`lib/prompts/workflow_dialogue_contexts.py`。
- 类型、冻结目录及精确消息认证：`lib/contexts/workflows/domain/dialogue_style_context.py`。
- 默认目录装配：`lib/bootstrap/dialogue_style_contexts.py`。
- 已采用经验的分类型冻结：`lib/bootstrap/contextual_reasoning_memory.py`，复用现有 Google 检索与本地向量。
- 逐轮选择：既有对话指导员；上下文只作为本轮建议。
- 原生注入与导出：`GenerateNativeCot`、`generate_native_turn` 及公开上下文来源认证。

离线验证覆盖逐轮切换、缺省回到通用、未知系统消息仍被拒绝、完整推理与历史保留、原审核提醒共存和旧版本兼容。离线协议测试不证明真实模型必然选对风格，也不代表生成质量已通过评审。

# 多轮生成、生产轮次与自动评审迁移验证

## 实际边界

本轮从提交 `78141cf` 的实现继续拆分三类执行流程，保留模块化单体。

- `GenerateMultiturnDialogue` 协调来源准备、导入对话原样评审、分角色逐轮生成和整段评审。`DialoguePort` 隔离来源文件和请求运行时；临时 `DialogueProgress` 不产生新的任务格式。
- `ExecuteProductionRounds` 协调已提交收据、下一候选窗口、最终核验和旧配方允许的有界补充；`GenerateProductionBatch` 管理窗口内依赖。来源索引、轮次文件、原子收据和事务由适配器拥有。
- `ReviewCandidate` 管理评分、修复、重复稿停止及待人工复核；`ReviewGeneratedCollections` 保留流式集合和 CoT/SFT 谱系；`ExecuteRepairBranch` 先认证全部父版本，再开始返工请求。

自动评审的纯内容与推理历史规则、模型返回协议、风格解析和运行时接入分开维护。旧 `workflow_production`、`workflow_review_repair`、`review_repair` 和 `reasoning_prefill_history` 路径保持单一实现的模块别名。通用 SFT/CoT 节点、请求运行时、资料缓存和人工增强会话还有各自的迁移边界，本轮不宣称整个生成引擎已重写。

## 行为对比

冻结重构前的实现，用同一份输入快照与离线客户端分别运行新旧执行器，并禁止真实 `ChatClient.chat`。

| 场景 | 比较内容 | 结果 |
| --- | --- | --- |
| 完整三轮对话 | 原生与训练导出、证据记录、13 个检查点、请求与输入统计 | 一致 |
| 普通有界生产 | 训练与证据文件、检查点、重复候选后的请求顺序 | 一致 |
| 质量优先生产 | 停止结果、训练与证据文件、检查点、请求顺序 | 一致 |
| 评审直接通过、修复后通过、重复稿停止、条件待复核 | 完整记录、推理字段、决定、请求顺序 | 四种均一致 |
| 生产请求中断后恢复 | 第二次尝试的产物、检查点和完整请求记录 | 一致 |
| 多轮评审返回无效结果后恢复 | 第二次尝试的产物、检查点和完整请求记录 | 一致 |

上述文件一致指逐字节一致；没有忽略推理或答案字段。18 项历史评审协议字符串及错误代码集合与原实现逐项相同。配方版本、提示词版本、持久化字段、序列化哈希算法和缓存键均未升级。

## 数据与架构核验

- 迁移前记录的 7,970 个既有任务与缓存文件保持原字节。
- 32 个历史数据集版本重新通过交付核验及统计，原产物字节未改变。
- 31 个含 Python 源码的 lib 目录都有 README；本轮补充各受影响目录的职责、入口、依赖及验证说明。
- 独立解释器禁止加载任何基础设施、组合根、页面和模型 SDK，仍可实际执行多轮、生产与候选评审用例。
- 内存端口验证百万记录按十个窗口调度，编排层不能遍历或展开记录替身。这是流式合同验证，不是百万条真实生成性能基准。
- 取消或收据写入失败不会推进轮次，并会退出会话；自然结束的单轮不能冒充多轮；重复稿不购买第二次评分；条件支持不明保留为待复核。

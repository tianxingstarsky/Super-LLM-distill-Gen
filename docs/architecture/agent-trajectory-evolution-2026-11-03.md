# 已记录 Agent 轨迹的流程与 CoT 优化

## 使用目的

这条路径编辑已有 Agent 轨迹，不要求本机具备原工具的执行环境。输入必须包含真实记录的用户、助手和工具消息；只有任务描述、尚无助手结果的输入不能伪装为完成轨迹。

新建工作流可显式选择 `agent_trajectory_optimization=True`，冻结 `agent_trajectory_optimization_version=1`。低层创建接口默认关闭，以保留旧调用；旧配方继续原本的工具重放路线。两种用途在 Agent 节点区分，不把旧重放检查当作新编辑路径的前提。

纯 Agent 优化的后续阶段显示“程序一致性核对”，只要求编辑作者模型，不要求单独的评审模型；不会执行的评审设置和绑定不进入新任务。旧重放、未标记配方及混合目标继续使用各自原有的评审合同。

默认每条轨迹最多请求一次编辑作者，处理最终助手的 CoT，并在同次提交中提供整段流程建议。请求使用该轮之前的完整真实历史；不自动对每一工具步骤购买一次编辑。其他助手轮推理保持原样；定点处理其他轮次时，只提供该轮当时可见的前缀。保留模式下，最终助手没有可编辑推理时不购买编辑调用；选择补写后才允许为该轮生成解释。

缺失推理继续服从输入节点的选择：保留、补写或排除。只有用户选择补写时才能合成缺失解释，且明确标成补写，不冒充原模型的真实原生推理。已有 CoT 采用可追溯局部修改，原文和完整响应保留。

## 不重放工具的边界

程序保留最终答案、工具定义、调用名、参数、调用 ID、工具返回、消息顺序和其余非推理字段；这些字段不由编辑模型重新输出。提交中的局部修改应用后，再绑定原稿与派生稿摘要。只说“结果相同”的模型判断不能替代程序核对。

流程建议与实际已执行轨迹分开保存。新增工具、改参数、删步、重排及依赖不明的修改不能直接冒充已经执行的训练动作；需要进一步确认的建议单独标记。已记录工具结果也不能挪到更早的 CoT 中充当当时已知事实。

结果与证据链保留不证明源答案本身正确。源结果未知就继续未知；格式、编辑一致性、原工具执行证据和语义质量是不同状态。发现源答案问题时保存问题，不为了配合它硬编推理。

## Google 经验接线

复用已安装的 [Google ReasoningBank](https://github.com/google-research/reasoning-bank) 原版提炼、检索与既有个人版本库，不增加另一套 Agent 调度引擎。

经验作用于真正发出 CoT 编辑请求的作者 system。采用版本随任务冻结，实际检索文字随请求检查点保存；恢复不重新读取“最新采用版”，也不因保存候选经验就热改正在执行的任务。继续复用现有 `reasoning` 角色，避免破坏旧的六角色快照。

学习材料保留原始助手行动与其后真实发生的工具观察、后续用户反馈。初始任务和后来的工具结果分开，不把未来观察打包成原用户一开始就知道的信息。未确认的结果和模型评语保留各自证据等级；不会因为编辑完成就自动记为成功经验。

提炼与采用沿用现有显式操作，不为每条样本自动增加学习或评审调用，也不自动无限返工。原版接入与安装见 [Google 接入说明](google-reasoning-bank-integration.md)。

任务结果未知的新观察可以先免费预览，再由操作者明确标注原任务达成或未达成；也可以保持未知或取消。预览立即释放认领，学习时重新核对同一记录及摘要，避免关闭页面后留下无法领取的观察。人工判断进入本次学习回执，不改写原观察，也不冒充工具执行验证；有明确既有评审结果的记录仍沿用原一键入口。

## 维护入口

- `workflows/application/optimize_recorded_agent.py::OptimizeRecordedAgent`：一次有检查点的编辑、派生记录与观察归档。
- `workflows/domain/agent_trajectory_optimization.py`：源协议、可编辑字段、局部补丁和结果一致性合同。
- `workflows/infrastructure/agent_optimization_adapter.py`、`bootstrap/agent_optimization.py`：固定经验版本、原版检索、实际 system 和既有模型请求设施。
- `prompts/workflow_agent_trajectory_optimization.py`：本功能独立提示词；聚合注册表不持有第二份正文。
- `presentation/streamlit/workflow_agent_settings.py`：原 Agent 节点内的模式、模型与提示词入口，不新开页面。

## 不执行工具的开源路线

- [Google ReasoningBank 的记录提炼](https://github.com/google-research/reasoning-bank/blob/main/WebArena/induce_memory.py)读取已有轨迹和结果信号，再请求模型归纳经验，提炼阶段不执行环境工具。
- [Agent Workflow Memory 的离线归纳](https://github.com/zorazrw/agent-workflow-memory/blob/main/mind2web/offline_induction.py)从已有记录提取可复用工作流。它仍需模型推断，得到的是流程建议，不是新的已执行证据。

工具模拟是另一类材料，不能冒充原记录。尤其不能把缓存未命中后会回源真实服务的入口当成“绝不调用工具”。需要改变原工具参数、顺序或实际动作时，应另行选择模拟或重放验证；相同的最终文字不能单独证明新路径正确。

## 子智能体数据的当前支持范围

DSH 导入器可以导入一个完整的子会话，保存 `parent_session`、委派深度、继承前缀和消息来源等审计信息。子会话中已经记录的推理、调用和返回可以作为单会话处理。

当前不会自动加载或关联其他父子会话、兄弟智能体与并行分支。生产来源投影和优化器仍使用平面消息历史，没有将这些父子审计字段组成协作图；Agent 训练导出是 `messages` 与可选 `tools`，不包含结构化父子图。因此只能称为部分支持，不能声称已完整支持多 Agent 协作轨迹优化。父会话如果只有子智能体的总结，不能凭空还原子智能体的内部过程。

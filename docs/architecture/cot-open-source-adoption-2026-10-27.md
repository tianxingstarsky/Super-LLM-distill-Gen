# CoT：按实际职责复用开源方案

本次接入范围是已有推理的保真风格编辑与明确参考答案核验。没有宣称已经移植 NeMo Skills 集群运行框架，也没有把工具格式正确当成训练数据质量证明。

## 新路径

新建官方 DeepSeek 严格工具配方冻结 `cot_style_transfer_version=2`。

1. 输入已有完整推理和答案；缺少推理时仍明确阻断。
2. 输入若提供明确数值参考，先用本地成熟验证器核验固定答案。错误或未解决时保留完整原稿，停止本次改写，不调用付费模型。没有参考时走原语义路径，不猜一个参考。
3. 作者调用 `edit_authored_candidate`，只交付需改段落和完整证据结构。程序验证基稿摘要、唯一匹配、字段与正文约束，再原子组装。答案不属于可编辑字段。
4. 对完整组装结果继续语义评审。用户限定选段时，评审与生成接收同一选段；真实用户/助手历史、完整候选、原稿仍保留。
5. 原始工具响应、编辑基稿、原作者会话、用量和来源工具轨迹继续存入原检查点。旧任务没有新版本标记，行为不变。训练导出字段不变。

风格仍由节点提示词控制，不规定固定段落、开头、步骤顺序、反问数量或最低长度。局部编辑减少重新撰写的范围，但不能保证模型不会申请大范围替换，也不能承诺供应商缓存一定命中。

## 可选数值参考输入

在原始输入记录的 `answer_reference` 中提供：

```json
{"version": 1, "kind": "numeric_expression", "expected": "\\frac{1}{2}"}
```

该字段随原始记录进入样本的 `source_context`。只有当最终答案本身是无单位数值表达式时适用，例如 `0.5`。`10cm`、多段公式、解释性文章、盒装结论或符号变量不属于此合同，会留待处理；不能把任意 NeMo 的 `expected_answer` 自动当成此类参考。`matched` 也只说明该数值相等，后续语义核验不会被跳过。

Math-Verify 的自由文本提取器适合评测中提取答案，但可能只取最后一个公式。因此此处使用同一开源依赖的完整表达式解析，关闭单位移除、坏公式修复和盒装答案提取。Windows 使用有时限的工作进程，避免 SDK 的嵌套多进程目标与应用线程信号问题。超时不是通过，且不触发 LLM 猜答案。

## 验证与未证明事项

- 真实 SDK 流式协议的离线测试覆盖直接编辑、检索后编辑、原作者继续修订、原生思考保留、摘要及唯一匹配、旧缓存恢复。
- Math-Verify 本地实测覆盖等价分数、微小数值差异、单位、冲突公式、超时、错误原答案零付费请求和收据复用。
- 已有真实论文案例用于离线重放。此前语义拒绝和人工发现的问题不会因新协议自动改判。
- 本轮没有新增付费 API 请求，没有新的真实通过率或平均单价。请求文本缩短不能等同于 token 或账单同比下降；需要后续同批受控实跑测量。

维护入口：`GenerateCot`、`GenerateWithSources`、`RepairAuthoredSubmission`、review 的 `VerifyReferenceAnswer`、`bootstrap/node_generation.py`。回归按本次受影响路径执行，不启动全仓测试。

## 内容抽检与成本取舍

新建保真改写草稿默认使用 20% 内容抽检，节点上可调 1–100%，也可选逐条严格核验。只有生成中推敲版本 7 支持该策略；旧冻结任务不改变，复制旧任务时明确恢复严格模式。20% 是工程起点，并非上游论文证明的最优值。

抽样依据来源与对话内容的稳定摘要，重试不会重新抽签，小批次不保证恰好命中指定比例。每条仍执行原有本地合同、正文、语言和范围检查；已知被拒绝的原稿先修复，不再付费润色。未抽中项保留完整答案、推理和原稿，记录 `not_assessed`，不创建虚假评审通过记录。任务报告展示覆盖情况；训练导出字段不变。

抽检时的语义指令将未明确要求的表达顺序、显式草稿形式、反问数量及润色程度作为建议；事实、单位、因果条件、真实历史和明确用户要求仍然保留。后续 JEV 或评分修正节点按各自配置执行，不因这项设置取消。

这项取舍参考上述 OpenThoughts 的过滤实验和 NVIDIA 按任务验证的边界，不代表放弃所有质量检查，也不意味着漏检已解决。三条既有真实记录的离线重放命中两条，历史请求数由 7 次推算为 6 次，历史费用从 ¥0.94269632 推算为 ¥0.74704304。只移除了未抽中条目的历史评审费用；没有重跑模型，没有新增 API 费用，没有重新判定质量或推测新提示词的结果。原有缺陷与待复核结论保持原样。

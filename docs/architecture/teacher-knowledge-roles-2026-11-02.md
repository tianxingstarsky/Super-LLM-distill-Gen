# 教师知识消息的角色对照

## 目的与范围

检查把教师知识从 system 改为 assistant，是否能减少闭卷知识应用样本中的来源旁白。此处的闭卷指学习者只看到问题；教师生成时仍接收知识。它不表示 API 调用改变了模型权重。

这是一次独立消息角色实验，尚未改变生产工作流的资料投放方式。生产原生请求目前由 `workflows/infrastructure/native_cot_messages.py` 将教师知识放入私有 system；训练消息另由原生生成用例组装。

## 对照方法

固定同一个分类数据／自由摘要问题、同一段 Self-Instruct 实例生成选段、默认经验 v6、模型与生成参数。两组均复用原问题，没有重新购买指导员规划。

| 组别 | 实际请求角色 |
| --- | --- |
| A | system 通用规则 → system 教师知识 → user 问题 |
| B | system 通用规则 → assistant 同文教师知识 → user 同题 |

最终 HTTP JSON 正文的唯一差异是 `messages[1].role`。没有附加“禁止提及资料”的措辞要求；没有旧答案、旧推理、工具或前缀续写。两组分别只生成一次，不额外调用评审。

assistant 教师块是程序投放的实验上下文，有独立来源记录，不是真实发生的助手发言。它不进入学习者消息，不成为额外的受监督助手轮。

## 实际观察

- A 的原生推理包含“需要基于给定文本”。
- B 的原生推理仍包含“这是基于给出的英文文本？需要根据文本回答”，正式答案包含“不是材料中已覆盖的情形”。
- 两组都正确给出固定标签分类采用 output-first、自由摘要采用 input-first 的核心映射；未观察到假称自己做过论文实验或引用不存在的先前对话。
- B 补充了多标签组合的建议，超出所投放选段；这不能自动算作已由原文支持的结论。

因此，本次简单换角色未消除来源旁白。只有单题、每组一次采样，不能据此断言哪种角色普遍更好。正文仍是论文式表述，模型可能据此将其作为参考文本；这一解释尚未通过另一次内容形态对照验证。

原生推理、答案、实际发包与来源指纹均保留。两份学习者草稿仍为 `not_assessed`；角色差异核验不等于语义质量通过。

## 消耗与后续边界

指定模型为 `deepseek-flash`。两次生成合计约 11.36 秒，按实际空闲时段 token 用量估算 ¥0.00727368，未核实账户扣费。模型别名、费率与高峰规则见 [DeepSeek 官方说明](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)。没有独立评审、资料改写或新增经验提炼调用。

若继续比较知识陈述与论文原文，应另立内容形态对照，保留事实、条件和原文来源，不将“换了角色”解释为知识已被验证。生产接入还需维护真实历史与程序投放知识的区分，并检查原作者续接会话和工具协议；不能把教师块直接加进训练对话。

## 初始系统规则与用途接线

前述角色实验只加载了 v6 通用推理经验，没有加载生产原生节点的完整模板。因此它证明这次简单换角色不足以消除来源旁白，不能证明完整生产模板也没有作用。

生产代码审计发现，普通请求的知识应用规则通过 `split_node_rules` 注入，而原生请求提前进入 `native_cot_messages`。生成后仍可能检查相应表达规范，生成前却缺少明确的用途分支。直接搬入原有整段规则也不合适：其中包含面向评审员的判分和定位命令，会再次混淆角色。

本次在原生功能所有者中新增 `workflow.cot_native_joint@1.7.0`。初始 system 的可编辑正文增加以下边界，不引入另一套评审器：

- 真实用户、当前回答者、辅助知识和行为规则分别承担任务、回答、事实支持与行为约束的职责。私有来源包装不冒充真实用户或过去的助手发言。
- 知识应用直接推导概念、关系、选择和条件，不叙述后台片段如何投放，也不把来源包装当成用户正在询问的事。
- 真实阅读、论文依据分析以及提示词、工具和模型配置设计仍可正常讨论对应对象。选段限制优先，不因模式名而扩大证据范围。
- 保留未知、条件、反例和真正影响结论的限制，不用虚构用户缺失信息、个人记忆、亲历实验或全文核验来掩饰证据不足。
- 两个输出通道都围绕实际任务。运行控制只影响行为，不变成评审旁白；不规定思考顺序、开头、句式和篇幅，也不删除返回的推理。

新原生任务以 `native_context_contract_version=1` 冻结用途信息。生成用例从冻结目标与当前问答合同取最小元数据，附入初始 system；不把全部合同、教师正文、私有标识或审查结论变成学习者消息。知识应用表达是否启用复用现有适用条件，文章选段仍受实际范围约束。无法确认的用途保持未知，不增加模型分类调用。

旧 1.0–1.6 文本和摘要保留，无标记的新快照兼容路径仍使用 1.6；已冻结任务和个人覆盖不迁移。节点内原有提示词编辑器可编辑 1.7 全文、恢复默认或保存个人版本，修改不会热换执行中的任务。

OpenAI 官方文档将消息权限与上下文分隔作为提示词设计的基础；本次只借鉴这些通用边界，不复制其他助手的私有提示词，也不将 OpenAI 的模型行为保证套用到 DeepSeek。[官方提示词指南](https://developers.openai.com/api/docs/guides/prompt-engineering)

离线验证使用原始 A/B 记录检查请求接线、历史兼容与完整内容保存。旧响应只能作为旧版观察记录，不能冒充 1.7 的生成结果；本次不调用 API，也不宣称来源旁白已在模型输出中消除。

# 教师知识消息的角色对照

## 目的与范围

检查把教师知识从 system 改为 assistant，是否能减少闭卷知识应用样本中的来源旁白。此处的闭卷指学习者只看到问题；教师生成时仍接收知识。它不表示 API 调用改变了模型权重。

这是一次独立消息角色实验，尚未改变生产工作流的资料投放方式。生产原生请求目前由 `workflows/infrastructure/native_cot_messages.py` 将教师知识放入私有 system；训练消息另由原生生成用例组装。

## 对照方法

固定同一个分类数据／自由摘要问题、同一段 Self-Instruct 实例生成选段、默认经验 v6、模型与生成参数。两组均复用原问题，没有重新购买指导员规划。

| 组别 | 实际请求角色 |
| --- | --- |
| A | system 通用规则 → system 教师知识 → user 问题 |
| B | system 通用规则 → assistant 同文教师知识 → user 同题 |

最终 HTTP JSON 正文的唯一差异是 `messages[1].role`。没有附加“禁止提及资料”的措辞要求；没有旧答案、旧推理、工具或前缀续写。两组分别只生成一次，不额外调用评审。

assistant 教师块是程序投放的实验上下文，有独立来源记录，不是真实发生的助手发言。它不进入学习者消息，不成为额外的受监督助手轮。

## 实际观察

- A 的原生推理包含“需要基于给定文本”。
- B 的原生推理仍包含“这是基于给出的英文文本？需要根据文本回答”，正式答案包含“不是材料中已覆盖的情形”。
- 两组都正确给出固定标签分类采用 output-first、自由摘要采用 input-first 的核心映射；未观察到假称自己做过论文实验或引用不存在的先前对话。
- B 补充了多标签组合的建议，超出所投放选段；这不能自动算作已由原文支持的结论。

因此，本次简单换角色未消除来源旁白。只有单题、每组一次采样，不能据此断言哪种角色普遍更好。正文仍是论文式表述，模型可能据此将其作为参考文本；这一解释尚未通过另一次内容形态对照验证。

原生推理、答案、实际发包与来源指纹均保留。两份学习者草稿仍为 `not_assessed`；角色差异核验不等于语义质量通过。

## 消耗与后续边界

指定模型为 `deepseek-flash`。两次生成合计约 11.36 秒，按实际空闲时段 token 用量估算 ¥0.00727368，未核实账户扣费。模型别名、费率与高峰规则见 [DeepSeek 官方说明](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)。没有独立评审、资料改写或新增经验提炼调用。

若继续比较知识陈述与论文原文，应另立内容形态对照，保留事实、条件和原文来源，不将“换了角色”解释为知识已被验证。生产接入还需维护真实历史与程序投放知识的区分，并检查原作者续接会话和工具协议；不能把教师块直接加进训练对话。

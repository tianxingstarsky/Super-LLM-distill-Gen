# 执行用例与文档边界整理验证

## 改动范围

普通工作流的运行生命周期、批次阶段顺序和完成状态从旧运行时分离。应用层通过 `RunSessionPort`、`BatchRuntimePort` 调用外部能力；原 `Workflow` 名字继续指向 `TrainingWorkflowRuntime`。批量取消改用显式异常类型，支持取消异常的子类。

本地文档语料准备通过 `DocumentTextPort` 读取文本。纯分块和 TeX 保留规则归文档领域，38 个 Docling 模块归文档基础设施。旧模块保持导入身份，旧 worker 脚本保持可执行。

新增 47 个目录 README，补充已有数据集领域说明，并提供代码导航、命名约定和更新后的迁移边界。31 个包含 Python 源码的 lib 目录均有说明，文档本地链接通过核对。

## 行为与隔离证据

- 新工作流和文档应用可在禁止加载 infrastructure、bootstrap、页面及模型/PDF/Word SDK 的独立解释器中加载；文档用例使用内存读取器实际执行。
- 普通批次用不可展开的百万条记录替身验证流程，不把记录集合转成列表。该测试验证接口的流式性质，不是百万条真实生成基准。
- 清洗先于指导和对话生成；偏好与 CoT 使用合格 SFT；最终推理处理先于打包。多个偏好格式复用同一对结果。
- 已结束任务只核验原产物；修正分支不启动原始生成批次；取消不重试，错误及取消均释放运行会话。
- 新旧执行器离线处理同一份 Markdown，`cpt.jsonl`、`cpt.records.json` 和输入统计完全一致。
- 32 个既有数据集版本重新核验和统计，全部原产物文件字节保持不变。
- 38 个 Docling 模块还原导入与路径迁移后，算法 AST 与重构前一致；TeX 算法也一致。解析策略常量与缓存签名未改。
- 在已安装的 Docling 2.140.0 / docling-core 2.102.0 环境中，新旧 worker 均通过隔离进程启动，返回相同 inspect 结果。没有下载权重或调用模型 API。

控制台交互回归单独运行，未与使用固定模拟端口的核心测试并行。本地控制台健康检查返回 200，44 个已有运行目录检查时没有活动任务；本轮未重启该服务。

## 重构过程中发现并处理的问题

移动 Docling 后修复了包内相对导入，以及仍属于旧基础设施的图片打包引用。新增静态路径检查，避免可选依赖未安装时掩盖同类错误。一个图片结构测试的注入目标更新为实际实现模块，原有“来源不变、可见性证据必须精确”的断言保留。

完整回归中唯一失败来自输入恢复测试仍向旧 `training_workflow.prepare_generation_rows` 注入禁止调用的替身。该调用已归新批次适配器，测试注入路径同步更新。取消、恢复、原始输入计数、处理上限以及 CPT 不展开无用候选的断言全部保留，相关文件复测通过。

批量执行原来比较异常类名字符串；改为类型判断，并验证取消子类不会变成重试或隔离样本。原有已保存状态值和恢复合同保持不变。

## 范围限制

剩余节点生成、多轮对话、批量轮次与自动评分修复仍在旧运行时中，尚未全部变成独立应用用例。资料库缓存与知识库的所有权也需要后续完整迁移。这次建立真实的依赖边界，没有宣称整个项目已经完成重写。

主 README 的产品介绍、界面布局、用户资料、参考图和 OpenCUA 子模块未在此轮修改。验证记录保存在本机 `.dataforge/ddd-maintainability-2026-10-23/`，不把任务数据或配置密钥提交到仓库。

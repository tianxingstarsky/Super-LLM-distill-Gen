# 知识表述编辑：两条真实推理验证

## 用途与归属

为内置知识问答增加一个独立的编辑角色，将泛指来源的旁白整理为能独立理解的知识表述。方法借鉴 [Decontextualization: Making Sentences Stand-Alone](https://aclanthology.org/2021.tacl-1.27/) 的保义目标；它不是自动证明推理正确的工具，也不把作者实验改成普遍事实。

- 提示词：`lib/prompts/workflow_knowledge_reasoning.py`，`workflow.knowledge_reasoning_editor`。
- 纯工具与补丁合同：`lib/contexts/workflows/domain/knowledge_reasoning_editor.py`。
- 原始推理、问题和固定答案保留；编辑器自己的原生思考只作审计，不冒充原回答者推理。
- 整理正文是派生解释，保留新旧摘要与实际替换，不继承旧稿的质量判断。
- 当前仅完成独立真实验证，尚未自动接入生产节点、默认导出或批量调度。

## 两个定位协议

1.0 提示词要求模型提交原文片段与替换文本，程序验证唯一匹配并原子应用。首次 B 调用抄漏了原文的段落分隔，实际工具响应成功，但局部替换被程序拒绝，原稿未改。没有修补 JSON、模糊匹配或放宽校验。

1.1 提示词改用程序生成的段落 ID。ID 绑定完整原稿指纹与段落位置；模型只提交 ID 和替换正文。程序持有原文及边界，未选段落、空行、CRLF 和尾部分隔原样保留。重复、未知及跨原稿 ID 均拒绝。旧 1.0 提示词与逐字定位合同保留。

`unchanged`、`edited`、`needs_content_repair` 仅描述编辑结果。所有收据仍标为 `not_assessed`；修改问题、答案、实验范围、数值、否定或确定性都不是单纯的表达整理。实际发生内容错误应单独记录，不因来源词语消失而算质量通过。

## 实际观察与剩余问题

两份已应用的整理正文都移除了泛指材料与内部控制字段的旁白，保留分类采用 output-first、自由摘要采用 input-first 的核心映射及标签正确性仍需检查的限制。完整原生推理和固定答案均未改变。

这不等于语义保真已经解决：

- A 把用户“一条流程、两批任务”的设定改写成“用户有两条流水线”，增加了不应认领的任务结构。
- B 保留“只能先”的过强判断，并从原稿“可行性高”新增“条件生成成本不高”的无依据成本判断。
- A 一次替换了整篇正文，B 的段落版修改了全部 14 段；不能把这次执行宣传为仅改少量字符或已经节省输出成本。

因此，本次证实了来源表达可以由编辑角色整理，以及程序编号能够消除这一次长文本抄写定位失败；没有证实通用语义保真、跨任务稳定性或生产质量。两份派生草稿继续保持未评审，以上问题保留待处理，未追加调用强求通过。

## 定向验证

7 项编辑合同测试覆盖原子应用、原文和答案摘要、固定答案问题定位、逐字锚点、重复段落、分隔符保留，以及未知、重复、跨原稿编号的拒绝。依赖边界与注册表／占位符相关验证 36 项通过；没有运行全仓回归。

## 原回答者续接编辑

随后按用户建议，只对同一份 A 原稿实测一次原作者上下文续接，不再另开知识编辑角色。`workflow.knowledge_reasoning_self_edit@1.0.0` 追加编辑操作说明，沿用与先前 A 编辑相同的严格字面补丁工具；不重新生成答案，不增加评审。

本次可验证的续接内容是实际捕获的原请求消息、真实助手的完整答案与 `reasoning_content`，以及冻结的模型绑定和端点。原消息前缀逐字保留，之后只有这份真实助手响应及一条应用 system 要求，没有新增 user、虚构 tool_call 或工具观察。早先隔离生成未保存 `author_session`，因此本次明确登记为从实际 HTTP 与完整响应恢复，不能冒称已有原作者身份收据或已认证历史凭据相同。生产接入仍应使用既有作者身份与前缀认证。

B 的知识块曾以合成 assistant 消息投放，并没有对应的历史原生推理。本次没有为它补造、空填或改写角色来强行续接，也没有购买 B 请求。DeepSeek 对携带 tools 的历史思考有单独要求，见 [官方思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。

本次 A 返回并应用了 4 处精确局部替换，保留大部分原分析，没有再次整体翻译成说明文；原问题、答案和原生推理存档不变，也未出现另开编辑上下文时的“两条流水线”改写。然而，“No need mention 根据材料”和“Final Chinese concise”等写作旁白仍留在派生推理，不能算整理完成或质量通过。

### 消息前缀与缓存的边界

实际 HTTP 对比确认：原来的 3 条消息逐字不变，之后追加完整真实助手响应和一条编辑 system 要求。模型、思考强度、输出上限和流式参数也保持不变。不过，原生成请求没有工具，续接编辑请求新增了严格工具定义及工具选择，路径从 `/v1/chat/completions` 变为 `/beta/chat/completions`。因此，消息数组的前缀一致不能证明服务端渲染、插入工具定义之后的模型 token 前缀也一致；目前没有服务端分词布局或逐段缓存命中的证据。

3,968 / 6,587 是本次全部输入的缓存比例，分母包含新增的真实助手响应、编辑要求和工具声明，不能读成旧前缀有四成失效。原生成输入 4,509 tokens 也不能直接作分母，宣称其中哪 3,968 个 tokens 被复用。后续若从新任务一开始采用同一套工具声明和接口路径，应在首轮冻结并保持；本次是首轮未声明工具的历史任务恢复，尚未完成这项前缀稳定性验证，不能追改原请求来制造命中。

此前另开编辑上下文的 A 也走 `/beta` 且使用同一工具；它与自编辑 A 的费用差异不应归因于路由不同。路由和工具变化只是在比较自编辑与最初生成请求时成立。

### 准确性优先的离线核对

用户要求额外消耗必须换来更准确的编辑，本例按任务事实、结论与条件的保留，以及无依据新增和未清理旁白分别核对，不以补丁可应用或来源词语消失替代语义正确。

| 一条流程、两批任务 | 改成“两条流水线” | 保留“两类批次” |
| 分类与自由摘要的生成顺序 | 核心映射保留 | 核心映射保留 |

| 编辑范围 | 原稿 2,958 字符整体改成 480 字符 | 4 处补丁，涉及原文 605 字符，新稿 2,572 字符 |

这是人工离线阅读观察，未增加独立模型评审，也未标记质量通过。新稿没有观察到新增领域事实，但不能据此证明一般任务都会更准确。另开编辑上下文也收到同一个问题、来源、完整原推理和固定答案；缺的是原来的 3 条对话消息及初始 system，不能称它完全没有业务上下文。自编辑说明还额外强调不能全篇翻译、摘要或重写，因此本例的保真改善不能单独归因于同一作者或上下文复用。

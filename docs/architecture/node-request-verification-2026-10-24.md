# SFT、CoT、模型请求与 DSH 会话导入验证

## 重构范围

以 `fe5dbc226f31b53fdcc98756c676297e412c7f98` 为基线，继续拆分模块化单体。

- SFT、指导式 SFT、原生与风格化 CoT、推理修剪由 workflows 应用层用例协调。纯生成规则在领域层，来源、检查点、模型绑定与流式记录由基础设施适配器提供。
- 节点请求意图使用内存值 `NodeModelRequest`。模型文本、JSON 与工具请求各有应用用例；SDK、三种协议报文和准入台账仍在基础设施层。
- 组合根负责装配；旧入口保留签名、模块身份和替换钩子。没有复制两套实现，也没有改动配方、提示词、缓存键或导出格式。

这些边界能在禁止加载基础设施和模型 SDK 的独立解释器中执行。剩余 CPT、偏好构造、资料缓存所有权及人工增强会话仍有独立的整理范围。

## DSH 手动导入

手动会话库来源目前仅支持 DSH。当前官方持久格式为 `.jsonl` 和 `.jsonl.zstd` 会话日志。SQLite 搜索索引无法还原完整会话，入口会解释原因并指向原始日志。

官方格式读取器、历史版本迁移与 Zstandard 处理位于独立 `plugins/dsh-dataforge` 包；Python 核心只接受版本化导入收据和规范会话。DSH SDK 不进入应用或领域层。当前适配依据官方仓库提交 `22ddee3792402c3e70ec5f86a63c3e3e895a2f60`。

入口为「Agent 上下文 → DSH 会话库 → 上传 → 预览 → 确认导入并选中」。确认后进入本机持久资料缓存。相同内容再次导入复用同一缓存路径；不会执行会话中的工具或调用模型。

导入保留真实角色、已有推理、工具调用 ID、工具结果、分支谱系和审计内容。没有推理时保持缺失。不完整、附件缺失、未知格式或原训练流程不能接受的记录会显示问题；不为使导入通过而改写历史或放宽训练校验。

两份由官方 SDK 读取的离线夹具通过了默认插件 CLI、Python 预览、确认缓存以及现有 `iter_source_units` 输入链路。其中一份包含 5 条消息、1 条推理和 1 组工具调用，另一份没有推理。原文件字节保持不变。

| 范围 | 结果 |
| --- | --- |
| 默认环境全量后端回归 | 8,053 通过、51 跳过；发现 1 处旧 CoT 分支的解析器导入路径错误 |

| 全套 UI 回归 | 185 通过 |
| 独立 DSH 插件 | 24 通过，无跳过 |
| 最终既有文件校验 | 7,971 个文件 SHA-256 完全不变，无缺失 |

修复把旧版 CoT JSON 回答分支的 `parse_json_robust` 导入改到 `models/contracts.py`，没有改动解析规则或断言。表中最终后端计数是全量回归、修复后对应回归和环境补测的合并结果，不表示重新运行了第二次全量测试。

唯一平台跳过是 `test_worker_ignoring_terminate_is_killed`，它验证 POSIX 进程忽略终止信号后的强制结束；Windows 的终止操作无法表达同一前提。没有新增跳过或降低校验。

真实桌面浏览器已完成 DSH 文件上传、预览、确认选中及缓存选择检查；后续重试、告警和中英文交互由 UI 回归覆盖。测试使用独立本机沙箱，没有向用户资料库添加夹具。

离线证据保存于本机 `.dataforge/ddd-nodes-2026-10-24/`；模型请求差异证据位于 `.dataforge/ddd-model-runtime-2026-10-24/`。夹具、缓存、截图、用户资料和密钥不随代码提交。

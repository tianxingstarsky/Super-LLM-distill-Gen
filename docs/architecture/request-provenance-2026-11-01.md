# 原生输出重复短语的输入溯源

更新：下文先保留离线调查过程，末尾补充两条干净上下文实测。干净实发正文不含相关规则，两份原始上游响应仍出现 `verbosity 5`；首次来源已定位到客户端可观察的响应边界，服务端内部原因仍未知。

本次离线核对两个 `native-system-notes` 样本的历史请求、原始响应、恢复收据和检查点。未调用模型 API，也未改写或删除原生推理。发现输入污染不等于证明所有同类输出具有同一原因。

## 实际投放内容

这两个样本来自同一段英文“课堂 PDF 演示”合成对话的第一、第二个助手轮。真实执行的是模型 API；场景和用户发言是合成的，不是两篇真实论文的解析结果。

原任务 `sources=[]`。场景明确说明没有已确认的文档内容、提取结果或可用文件工具。对话提到了 PDF，但没有投放实际 PDF 正文，因此这次不能把问题归因于上传论文。

若“资料”泛指程序组装的全部输入，已确认其中存在问题：复跑脚本将后来记录里的历史 `reasoning_content` 补入原请求，并保留旧返工提示。旧冻结规则中的“短、简洁”等引导也不等于实际用户指定了某个数值篇幅等级。

| SDK 与缓存 | 当前 SDK 经 MockTransport 重建没有新增提示词；响应、展示值和唯一检查点一致。该结果不是历史网络抓包，也不能证明服务端不存在其他指令。 |
| 观测缺口 | 旧实验的 SDK 参数白名单遗漏 `reasoning_effort`。该遗漏说明日志不完整，本身不能解释具体数值的来源。 |

因此撤回此前直接称为“幻觉”的定性，也不将尚未验证的上游泄漏写成结论。本次覆盖这两个样本及其来源，不表示全库材料都已排除污染。

## 后续诊断原则

保留原稿、完整推理、审核记录及来源摘要。原生工具续写按原协议回传必要历史；新发起的独立对照不从后来训练记录额外补塞历史推理。不能为排查污染而删除存档或改变冻结任务。

已准备公开对话，以及公开对话加 system 注意事项两种对照，每轮各一份。它们仅准备，尚未执行，不算质量改进或新的成功样本。除上下文外，使用相同的当前请求参数。

下次隔离实测应在实际 HTTPX 请求边界保存完整 JSON 正文、正文摘要及目标 host/path，不只保存 SDK 参数白名单；认证头不写入诊断记录。区分客户端实发正文、上游返回、程序回填和训练投影，不能把未观察到的服务端行为当作已证实事实。

本地原始证据保存在 `.dataforge/verbosity-leak-audit-20261101/`，属于运行记录，不作为产品默认数据入库。其中 `provenance.json` 保存逐请求来源，`source-material-audit.json` 保存原始场景和输入来源摘要，`wire-audit.json` 保存离线传输及检查点核对。

## 干净上下文实测

用户随后授权两条隔离对照，已于 2026-11-01 完成。请求仅保留原公开对话：01 为 `user`，02 为 `user / assistant / user`。第二条保留原历史助手正文，不换成新第一条，防止同时改变对话内容。两条均无 system 消息、历史推理字段、返工说明或 tools，不使用此前准备的“公开对话加注意事项”对照。

调用配置保持 `deepseek-flash`、`thinking=enabled`、`reasoning_effort=low`、`max_tokens=32768`、`temperature=0.7`。模型列表声明 `DeepSeek-V4.1-Flash`，客户端配置为 `direct`，保持 TLS 默认校验并忽略环境代理。调用经现有配置加载器和 OpenAI SDK，绕开工作流上下文组装与检查点恢复，用来隔离输入来源，不冒充整条产品流程的质量验收。

使用 [诊断脚本](../../scripts/diagnostics/README.md) 在最终 HTTPX 请求边界保存完整 JSON 实体正文、原始 UTF-8 和 SHA-256，并在发出前验证它与冻结请求逐字段相同。完整原始响应正文、解析值和摘要一并保存；请求头和凭据不公开。实际发送两次生成请求，查询一次模型列表，无自动重试、返工或独立模型评审。旧原始请求摘要和冻结输入保持一致。

### 实测结果

两份干净请求均没有 `verbosity` 一词；两份原始响应的原生推理各出现两处 `verbosity 5`，最终答案未包含这个短语。首次可见位置已经是上游返回的原始响应，排除了这两次请求正文中旧规则、旧推理或返工说明的注入。不能继续把本次现象归因于本地历史回灌。

客户端证据仍不能分清服务端默认/隐藏指令、模型训练形成的固定表达习惯或其他服务内部处理。模型列表及响应名称是服务声明，不是独立权重认证；未向提供方发送工单，也未增加额外付费探测。记录有 completion ID，但响应未返回 `x-request-id`。

另据 [DeepSeek 思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)，不带 tools 的请求会忽略历史 `reasoning_content`，带 tools 时才要求完整回传并拼接。因此，旧调查的“21/22 请求含该字段”说明输入记录不独立，但不能被解读为 21 次输出都由该字段引起。该说明还指出思考模式会忽略 temperature；保留参数只是为了请求一致，不能当作确定性采样保证。

# 按训练目标组织的数据工作台设计：CPT / SFT / DPO

状态：**分层实现中**。自动工作流的来源快照、阶段可视化、断点执行、七类目标初版与 JEV 评分已落地，见 [自动工作流使用说明](automatic-workflows.md)。本文件聚焦工作流之外的数据集修订、统一人工审核、版本划分与发布治理；下面描述的完整数据集目录和发布流程仍是设计提案。

## 1. 结论与当前问题

需要管理的不是命令，而是“哪份原始资料，按哪个训练目标和质量标准，加工成哪个可追溯版本”。因此不能只给「管线运行」增加三个分类标签。

当前缺口有代码依据：

| 位置 | 当前行为 | 需要改变的管理语义 |
| --- | --- | --- |
| `lib/webapp.py` 的 `page_run` | 平铺预设 + 通用 argparse 表单 | 先选训练目标，再给相关输入与加工模板 |
| `lib/webapp.py` 的 `page_assets` | 按文件名含 dpo/corpus/samples 猜类型 | 以显式数据集登记和 schema 验证为准 |
| `lib/review_editor.py` 的 `normalize_sample` | 面向 messages/conversations | 语料和偏好对需要独立预览/审核模型 |
| `lib/cli.py` 的 `cmd_export` | 默认读取 rollout_samples、corpus/docs、dpo_pairs | 显式选择数据集修订，不能隐式带入旁路文件 |
| `lib/cli.py` 的 `cmd_dpo_merge` | 写 dpo_all，但默认导出仍读取 dpo_pairs | 合并结果必须作为可选、可追踪产物进入发布 |
| `lib/quality.py` 的 `report` | 按对话结构标错，未建立修复/隔离流转 | 分目标验证并将每条问题导向明确去处 |
| `lib/exporters.py` 的 `to_minimind_dpo` | 主要验证两分支非空 | 还要验证共享上下文、差异、偏好依据、训练模板转换后的差异 |
| `lib/exporters.py` 的 `export_minimind` | CPT 只取 text；缺字段可能静默跳过 | 结构化字段映射、预览、逐条统计，不得静默丢数据 |
| `lib/dpo_enhance.py` 的 `merge_pairs` | 按 ID 去重，输出仅保留核心字段 | 保留来源、偏好依据和分数证据 |

导出版本和审核修订已有不可变保护，但多数中间产物仍是固定文件。`commands.yaml` 的命令分组已有基础，不能直接等同训练目标；一个步骤可能同时产生 SFT 和 DPO。现有 distilabel YAML 主要覆盖 smoke/Magpie，不应把所有现有 CLI 工具宣称为已完成的 distilabel 管线。

## 2. 四个概念必须分开

1. **原始来源**：用户已有目录中的 JSONL、文档、表格、图像、聊天或工具轨迹。来源不是 SFT，也不需要先人为改名。
2. **训练目标**：CPT、SFT、DPO。决定训练单元和质量合同。
3. **加工阶段**：已登记、规范化、待修复、待审核、可发布等。阶段不是新的训练目标。
4. **导出配置**：目标训练框架、格式、tokenizer、chat template、推理字段和 loss-mask 支持。导出格式不是数据质量等级。

一个来源可派生多个目标数据集，彼此独立：

```text
已有结构化技术资料
  ├─ CPT：忠实语料 → 清洗/切块 → 知识语料版本
  ├─ SFT：构造任务 → 有依据的推理与答案 → 对话版本
  └─ DPO：同任务的候选比较 → 证据充分的偏好对版本
```

不要求 CPT 必须先转 SFT，不要求每条 SFT 必须生成 DPO，不因勾选一个来源就自动启动所有分支或产生模型费用。同源内容的版本关系和数据划分仍统一追踪。

图文、工具使用、GUI、翻译、领域、语言和长度属于独立维度，不与 CPT/SFT/DPO 并列混成一层菜单。例如一个数据集可以是「SFT / 图文 / 工具轨迹 / 中文 / 推理必需」。同一加工步骤可以服务多个目标；以后扩展其他目标时需新增对应 schema、验证合同、审核视图和导出支持，不能仅添加一个可选标签。

## 3. 以训练目标为中心的界面

### 3.1 工作区首页

保留「打开已有文件夹」语义。原始目录不搬动，不创建空工作区，不重建失联路径。进入文件夹后提供：

```text
当前文件夹 / 工作区                 全局预算 · 运行中任务 · 模型与密钥

[全部] [CPT 知识语料] [SFT 指令对话] [DPO 偏好对] [待分类]

技术知识库-CPT    v3    可发布    18,200 段   来源 12 项   打开 / 派生新目标
技术问答-SFT      v2    待审核       820 条   问题 43 条   继续审核
工具纠错-DPO      v1    待修复       210 对   阻断 17 对   处理问题

[登记来源] [创建目标数据集] [运行记录] [已发布版本]
```

上面计数仅为界面示意，不是当前数据统计。界面显示目标、修订、状态、有效数量、阻断原因和下一项主要动作；模型、预算和工作区身份始终可达。

文件只是数据集的来源或产物，不再是唯一管理单位。`foo.jsonl` 可以有明确的 DPO 身份，`dpo_notes.jsonl` 也不能凭名字被当偏好对。

### 3.2 新建一个目标数据集

向导只有四步，复杂选项按需展开：

1. **目标**：CPT / SFT / DPO，并显示输出结构示例。
2. **来源与映射**：从当前目录或已登记的数据集修订中选择；自动识别格式，但必须展示识别依据、字段覆盖和异常行。异构 JSONL 可分组登记，不能把混合文件强行按第一行套 schema。
3. **加工模板**：只显示适配输入和目标的模板，默认带安全清洗；说明本地步骤、模型步骤、预计费用和外发范围。
4. **预检与试运行**：先做本地只读预检；模型小批试运行需要已有授权。显示输入→输出对照、剔除原因、估算产量和成本后，再明确运行全量。

字段映射保存为可复用配置。不会要求用户每次手写命令、选择中间 JSONL 或在多个页面之间复制路径。新建的是目标数据集登记，不是新建或复制用户工作区目录。

### 3.3 数据集详情

固定页头：名称 / 目标 / 当前修订 / 质量状态 / 来源摘要 / 运行状态。页内标签：

- **样本**：按目标渲染，问题筛选与批处理入口。
- **加工**：当前配方的可读步骤、输入/输出、费用、配置差异；不是要求用户画复杂节点图。
- **问题与审核**：只修复失败项、查看差异、派发审核、裁决冲突。
- **版本与来源**：父版本、来源快照、操作者、规则/模型变化、数量差异。
- **发布**：选择目标版本、训练配置和数据划分，预检通过后发布。

默认不呈现所有 CLI 参数。原 CLI 保留为高级入口；“查看等价命令”应能重现同一不可变运行配置。

## 4. CPT：结构化内容可直接进入，但不能随意压平

### 默认模板：结构化知识入库（无模型调用）

`读取/映射 → 结构与权限预检 → 规则清洗 → 精确/近似去重 → 结构感知切块 → 语料核对 → 发布`

支持优先级：现有 text 型 JSONL、Markdown/文本；新增字段映射 JSON/JSONL；表格和嵌套 blocks 通过对应解析器逐步接入。每种格式只有解析器和往返/覆盖测试通过才在 UI 标为可用，不能显示一个“支持所有结构化内容”的空入口。

CPT 不强制套 user/assistant 对话，不生成装饰性思维链。对结构化输入，用户选择忠实的序列化方式：

- 标题 + 正文：保留层级和顺序。
- 问答资料：保留「问题/答案」栏目，不自动伪造聊天角色。
- 表格：保留列名、单位、行关系；按行/表块序列化，缺单位或跨页表头需要提示。
- 嵌套对象或代码：明确字段集合与稳定序列化模板，不使用不透明的 `str(dict)`。

原始结构保留在来源中，内部规范化记录保留结构锚点和字段映射；面向文本训练的序列化不等于可以无损还原原结构，界面必须显示会遗漏/变换哪些字段，并阻断未确认的损失。序列化模板参与配方哈希，每段保留 snapshot_id、文档/记录 ID、源字段或片段位置。日志中的 reasoning/CoT、内部提示和凭据默认不进入 CPT 字段映射，不能因为同在一个对象里就全部拼入训练文本。

### 质量合同

- 文本非空，解析/编码正确；来源、授权/许可、文档/行定位可追溯。
- 无明显密钥、隐私外泄、乱码、导航噪声与高重复；规则删除能定位到原字段/片段。
- 切块保留标题上下文，不切断代码/公式/表格语义；长度按目标 tokenizer 计算，字符数只能作为估算。
- exact 去重可自动处理；近似去重给出相似依据，避免删掉数值不同的重要版本。
- 来源变更后旧运行不能继续假装读的是原快照。

CPT 审核按文档/段落进行：左侧来源定位，中间原结构与训练文本对照，右侧保留、剔除或调整映射。规则性问题允许按同规则批处理，但先展示受影响范围和样本差异。

“无需改成对话”不等于“无需清洗、权利检查和发布门”。CPT 后续可以有专门的分层抽检策略；在其政策、覆盖率和风险阈值经明确批准前，不能套用或绕过现有 SFT G3 门。

## 5. SFT：任务有效、推理可信、上下文完整

### 默认模板：高质量推理对话

`解析来源 → 重建任务/完整上下文 → 分类问题 → 规则清洗 → 有依据的修复/推理构建 → 验证答案与过程 → 去重与分布检查 → 审核 → 发布`

提供至少两种输入路径：

- **已有会话/工具日志**：保留合法的消息、推理、工具 ID、参数、返回与多模态关联，检测上下文缺失、未解决错误、无效回合和隐私。
- **结构化知识/文档**：先构造可回答任务和证据范围，再生成答案与解释。不能把每行随便套成问答，也不能把文档中没有的结论编成标准答案。

按本次需求，默认质量合同为 **reasoning_required（要求有效推理）**。不以“存在 reasoning_content 字段”作为合格条件：

- 原始可用推理须验证与任务、证据和答案一致，并保留来源。
- 缺推理时生成的是有依据、可检查的推理解答/解释，标记为 synthetic，而不是声称恢复了原模型不可见的内部思考。
- 无法给出有价值的推理或无法验证时进入待修复/隔离，不用空串、模板句或冗长自言自语凑数。
- 系统/用户/工具消息不要求有思考；无最终答案的工具调用消息也不能机械套用最终回答合同。
- 简单抽取、格式变换等任务若采用不要求推理的 SFT 配方，必须由用户显式选取另一合同并单独统计；不能暗中降低默认标准。

推理内部统一分字段保存；是否输出特殊 token 由导出配置决定。DPO/SFT 不因选择“思维链模板”就自动增加 token 数，推理长度只是上限和任务匹配约束，不是质量分。

生成与验证分为不同步骤：优先采用确定性答案/引用核对、授权沙箱中的执行验证及独立评审，不能把同一次模型的自我肯定当证明。开放问题无法机械证明正确时显式标注证据等级和人工审核需求。生成项记录模型/提示版本、证据片段和来源标签；同时记录来源授权与教师模型输出使用条件，未知商用训练许可要阻断对应发布，不能用一个未经核验的“商用可用”标签替代授权依据。

### 错误操作与工具因果

原轨迹只读。正样本不能继续教失败操作，但也不能只删除出错消息后让后文引用不存在的工具结果：

1. 有可靠纠正证据时，生成新的正确演示，完整重建调用与返回关系。
2. 不能重放、没有已验证工具结果时，不伪造执行成功；转为文本化错误教训（有来源）或隔离待补证。
3. 有可比较的真实负例时可以派生 DPO 候选，仍需满足偏好对合同。
4. 工具重放可能有外部副作用，默认禁用；只有授权的只读/沙箱工具可执行，不能为验收去触碰用户运行中的训练或生产任务。

### 人工操作

复用现有固定审核工作台，增加问题原因、来源证据和修订差异。新增“结构性重建”动作可用于拆分/合并/重建会话，但必须是带版本绑定的新修订接口，不能放宽当前单字段编辑接口去修改角色和工具元数据。

审核者可以选择“只修复这类问题”，不必重新运行整批，也不必为已通过样本重复付费。

## 6. DPO：审核的是有依据的比较，不是两段字符串

### 默认模板：同任务偏好对

`读取现有偏好对/候选会话 → 对齐共同 prompt → 检查两分支 → 识别偏好维度 → 验证胜负依据 → 去重/冲突检测 → 偏好审核 → 发布`

可选输入：

- 已有 prompt/chosen/rejected：优先验证，合格时直接保留，不能为了“重建”全部重新生成。
- 真实纠错轨迹：从同一决策点提取坏选择与已验证的改正，确保两分支上下文相同。
- 只有一个答案：需单独启用候选生成/修订，显示预计费用；候选生成不等于负例已成立。

### 不可放宽的校验

- 同一任务、同一共享上下文；两分支使用“续写”或“完整会话”的表示必须明确，不能混用后重复拼接 prompt。
- chosen 满足正确性和目标合同；rejected 有具体偏好理由和来源，负例不能靠随机损坏、隐私泄露、丢消息等捷径制造。
- 两分支非空，角色/工具结构合法；规范化后和目标训练模板渲染后均不相同。渲染/截断后退化成同文的 pair 必须阻断。
- 偏好可以是正确性、安全性、工具行为、表达风格或推理质量；各维度分开统计，不用一个含糊总分掩盖相互冲突。
- judge 解析失败就是失败/待重试，不能返回默认分数伪装有效证据。模型分差只是证据之一，不等于真实偏好成立。
- 保留来源、候选生成方式、判断规则、模型身份/版本、分数和偏好依据；合并不能删掉这些信息。
- 检查同一对反向标签、近重复 pair、长度偏好和生成/评审同模型的相关偏差；难分胜负或两个都坏时隔离，不强行配对。

### 推理合同

默认 DPO 数据集同样采用推理合同，但 chosen 与 rejected 的要求不同：chosen 的推理必须可验证；rejected 可以保留被明确标注的推理错误，不能为了让两边“正确”而洗掉偏好差异。只有缺失推理本身就是明确偏好维度时，才在显式配方下允许一边缺推理，并单独报告。

### 偏好审核工作面

顶部只显示一次共享 prompt，中部双列并排 chosen/rejected、同步定位和字段差异；侧边固定展示证据、偏好维度和判定。

操作为：**接受这对、交换胜负后另存新版本、两者都不合格、无法判断、修复当前分支**。接受、否决和弃权分开记录。交换胜负或编辑任一分支都产生新内容哈希，旧票不自动认证新 pair。

底层审核存储需增加 `record_kind` 和对应 payload schema；复用身份、授权、幂等、版本绑定，不能将 DPO 偷塞进一个 SFT messages 字段而丢掉比较语义。三类审核共用队列/导航/草稿保护外壳，仅阅读布局、验证合同和动作不同，不维护三套相互漂移的应用。

原始内容票绑定 context + chosen + rejected 的内容身份及审核政策；训练就绪证据还绑定目标模板版本和质量合同。改内容或交换标签必须重新审核；只改模板时至少重做目标渲染验证，若改变可见语义/训练信号则要求重新审核，不把旧内容票直接当新训练配置的批准。

## 7. 清洗不是删除按钮：四个独立去向

每次运行对每个输入单元有一个最终处置，处理动作另外记录：

| 最终去向 | 含义 |
| --- | --- |
| eligible | 通过合同，可进入对应审核/发布候选，不等于自动放量 |
| repair_pending | 有明确可修复原因，等待修复或补证 |
| quarantined | 不满足使用条件，隔离并记录原因 |
| duplicate | 已按指定策略归为重复，记录代表样本和相似依据 |

“修复成功”是动作/来源标记，成功后进入 eligible，不能在漏斗中双重计数。切块、拆分、配对是一对多/多对一关系，因此分别显示输入处置统计与输出产生统计，而不是声称输入条数必然等于输出条数。

**隔离内容 ≠ DPO rejected。** 前者是不可直接训练的原料，后者是具备上下文和偏好证据的训练负例。原文/敏感片段默认不出现在普通日志；问题报告使用 ID、位置、原因码和脱敏摘要。只在获授权的来源查看界面展示必要内容。

修改清洗规则产生新的配方修订；只重跑受影响样本，保留原处置和修订链。人工可将误杀样本恢复为新的候选，但不能删除旧审计历史。

## 8. 数据模型、持久化与并发

### 8.1 管理实体（拟新增）

- `SourceSnapshot`：来源引用、读取范围、大小/哈希、授权状态、结构识别、字段映射版本。快照是内容身份，不意味着必须复制整份大数据。
- `CollectionRevision`：数据集 ID、目标、schema 版本、质量合同、父修订、来源关系、产物和统计。已物化修订不可覆盖。
- `RecipeRevision`：可复用步骤、有序配置、模型角色引用、规则/提示版本、输入/输出 schema；共享配置不包含密钥。
- `Run`：执行者、工作区、数据集、输入/配方固定版本、阶段状态、checkpoint、费用、产物、错误、重试/父运行关系。
- `ReviewEvidence`：记录类型、内容哈希、审核身份、政策版本、判定与依据；保持身份授权隔离。
- `Release`：显式数据集修订、目标训练配置、数据划分、质量与审核证据、文件哈希、数量和转换损失报告。

记录级来源关系含 `parent_ids/source_spans/transform_id/content_hash`，DPO 两分支独立来源，不能只在目录层写一句“来自某文件”。来源缺失或变化时显示 source_changed/source_unavailable，不重建目录，不沿用旧身份继续读取。

### 8.2 存储方式

复用现有 `WS.output_at`。拟新增目录均在用户已有工作区的输出根内，default 仍走项目 data/output：

```text
<output>/catalog.sqlite
<output>/datasets/<dataset_id>/revisions/<revision_id>/manifest.json
<output>/runs/<run_id>/...         # 阶段分片、checkpoint、问题清单、运行清单
<output>/export/<release_id>/...   # 不可变发布
```

清单/目录索引用 SQLite WAL 和事务，产物为有界分片 JSONL/已有格式；不新增数据库服务。不要把所有样本全文塞进管理索引，也不要每次打开页面重扫源文件。

写入先在本运行的 pending 路径进行，校验完成后原子发布 manifest；index 只将完整 manifest 标为可用。中断时保留 interrupted 状态；重启可从 manifest 修复索引，不能仅凭文件存在认定成功。多个用户同时执行同配方也使用不同 run_id，不能继续写同一个 docs.jsonl/dpo_all.jsonl。

### 8.3 运行状态与恢复

运行状态：queued / running / blocked / succeeded / failed / interrupted / cancel_requested / cancelled。数据集质量状态另存，不能把进程退出码 0 等同可发布。

复用现有隐藏子进程和 Job 启动方式，增加持久化登记、阶段 checkpoint、跨进程租约/锁和去重请求 ID；不是另造智能体框架。刷新页面从持久化状态恢复，不依赖单个浏览器 session_state。

取消只面向本项目登记且重新核验身份的运行/子进程；在分片边界协作停止，不用泛化 taskkill。进程崩溃由打开页面/下次启动时按登记核对并标记，不增加 watchdog 或自动重启循环。

恢复缓存以输入哈希、配方、步骤代码/适配器版本、规则/模型/提示版本和人工修订身份为键。远程请求已发出但回执丢失时，状态为“结果未知”；除非供应商提供可验证幂等性，否则不能自动重放收费请求并承诺零重复费用。

多角色并发的 G0 必须采用事务性额度预留与结算，按请求 ID 幂等处理；结果未知的费用不能在取消时直接当作未发生释放。取消标记让各 Step/子角色可见，未提交的分片不会被发布拾取。跨进程锁采用固定获取顺序与超时，目录索引和审核写入不得相互持锁等待。

来源或配方有新版时，历史运行保留可重现价值，显示“有更新”而不是自动判为无效；继续使用固定历史修订须明确选取。若发生来源授权撤回、质量政策阻断或证据失效，则另有 invalidated 状态阻止新发布，不能把正常版本更新与合规失效混为一谈。

多人共享同一中心可复用当前 SQLite 事务；各人自己的主机仍通过已有身份 API/dsh 任务接入。不要将 SQLite 文件放网络共享盘当分布式数据库。新增 CPT/DPO 远程审核协议需版本协商，不兼容的旧 agent 明确拒绝，不伪装成 SFT。

## 9. distilabel、命令注册和 dsh 的职责

- **distilabel**：执行规范化、规则清洗、重建、验证、去重等数据步骤；将现有纯函数逐步包装为 Step/GlobalStep/LLM Step，保留成熟管线的批处理和 checkpoint 能力。
- **现有 CLI**：保留可脚本调用能力；新增目标运行入口最终调用同一配方，不另建一套隐藏逻辑。
- **命令/步骤注册表**：扩展 `accepts`、`emits`、`objectives`、`cost_class`、`requires`、`implemented` 等元数据。一个步骤可以同时产生 conversation/preference，不用单值 type 强行归类。模板只组合已实现的步骤。
- **dsh**：读取技能和当前不可变任务清单，按生成/修复/评审角色及各自配置派发子智能体，回报阶段产物与证据；不能把 Streamlit 工作台叫 dsh 原生 UI。
- **审计/闸门**：每个步骤执行前校验，而不只检查一个菜单标签。G0 全局硬预算，G1 绑定来源/外发范围，G3 绑定发布输入版本。配方改变来源或模型外发范围时重新校验授权。

模型引用复用「模型与密钥」管理；任务清单只放后端别名，不放 API key。区分本地计算与远程处理：对数据外发的授权不能仅因使用免费模型就省略。

四层去重应显式成为版本化的质量步骤：导入身份、精确内容、MinHash 近似、embedding 语义。复用成熟实现；当前尚未贯通的层级在 UI 显示未执行，不能把宣称的四层写成既有能力。embedding 可能有费用/外发，照常受闸门约束。

## 10. 发布：训练目标和训练格式双重验证

发布入口从目标数据集进入，不再默认附带同目录下的 CPT/DPO 文件。步骤为：

1. 固定数据集修订、合同与审核证据。
2. 选择训练目标/框架配置；只显示已经实现并验证兼容的组合。
3. 固定 tokenizer/chat template、推理处理、图文/工具支持、最大长度和 loss-mask 策略。
4. 以来源组、派生关系和重复簇共同形成的分组划分 train/validation/test，再在各划分内组合/打包；同源 CPT 段、SFT 问答、DPO 两分支不得泄漏到不同划分。分组规则、cluster 版本、seed 和分配清单冻结并跨目标共用，不每次随机重分。若已有评测集，则先核对其冻结身份；后续数据命中冻结评测组时拦截，不静默合入训练。
5. 对目标渲染结果再校验：字段、token、推理是否真的参与期望训练、图像/工具引用、DPO 两分支是否仍有差异。未知模板支持不能默许降级。
6. 检查当前发布合同、质量结果和 G3，显示通过/阻断及来源覆盖率，再写不可变发布。

每个文件给出转换前数量、成功数量、排除数量、原因、schema 和 SHA-256。无有效输出、必需字段丢失、内容截断后失去任务意义时发布失败；不得写一个空训练文件后显示“成功”。草稿预览与 training_ready 发布明确区分，草稿不取得“已通过训练验证”标签。

CPT 大语料以后允许按来源/风险分层抽检的政策，但这是显式新质量合同，不是将现有 90% SFT 审核门偷偷改低；现有审核票与 G3 不自动认可新的合同。

多目标组合发布使用 bundle 清单引用各自已经通过的修订，不能把一个 SFT 的 G3 批准当成同目录 CPT/DPO 的批准。minimind 仅为可选输出格式参照，不是项目组织逻辑或关联依赖。

## 11. 实施顺序与验收标准

本节是后续实施切片，不是当前完成声明。

### 第一片：打通目标登记到显式发布（先解决管理断点）

- 增加来源/目标数据集/版本登记、schema 预检和三类预览。
- 登记旧文件时只读检测、人工确认类型，不搬迁、不覆盖；不推断它已通过质量门。
- 导出选择数据集修订，DPO 合并产物能被显式选中；不隐式携带旁路文件。
- 加 DPO 非退化、CPT 类型/空输出、来源与转换损失阻断。
- 接入按目标合同的审核/发布，未实现合同不显示“可发布”。

### 第二片：可重现加工闭环

- 建立配方修订和 distilabel 封装，贯通处理/修复/隔离/去重的原因账本。
- 运行持久化、阶段恢复、费用边界、跨会话并发保护。
- 默认推理合同及目标训练模板的二次验证。
- 用户可以只重试问题子集，不重写已经确认的版本。

### 第三片：协作与规模化审核

- CPT 原文/序列化对照，DPO 双分支审阅，SFT 结构重建与差异审核。
- 记录类型扩展后的身份/权限/旧协议兼容；冲突不静默覆盖。
- dsh 读任务/技能、按角色配置派队，保留本机各自主机 Agent 模式。
- 数据分布、跨目标划分和 bundle 发布。

### 必须用真实流程通过的验收

1. 选一个已有混合目录，不重命名文件、不手写命令，分别创建 CPT/SFT/DPO 目标数据集；自动识别不确定项不能静默误分。
2. CPT 的嵌套结构、单位、表头和代码块有明确序列化预览；缺 text、非法类型、全部被过滤都被解释而不是静默成功。
3. SFT 缺推理进入重建/待修复；重建内容有来源标记，伪造工具成功结果被阻断，其他消息与原数据保持不变。
4. 已有合格数据不必无理由再生成；本地步骤不消耗模型额度，未授权模型步骤不执行。
5. DPO 同文、不同 prompt、反向冲突、模板后同文、两边都坏、judge 解析失败均有独立失败测试；合并保留完整来源证据并进入选定导出。
6. 一次一对多切块/会话拆分后，输入处置和输出数量都可核对；隔离记录不会自动成为 rejected。
7. 同源的 CPT/SFT/DPO 及近重复组不跨训练/评测划分；已批准修订被编辑后不能继续借旧审核票发布。
8. 两个身份同时运行同配方不互相覆盖；刷新能恢复运行详情；取消只影响自己的已登记任务；中断/未知费用状态可见。
9. CPT 文档、SFT 长对话、DPO 双列审核在桌面视口内主要动作持续可达，默认渲染，仅局部编辑，保存失败保留草稿；不能仅以单测代替人工交互验收。
10. 发布 manifest 精确列出显式选中的修订与转换统计，旧文件、旧发布、私有配置、全局默认工作区均未改动。

## 12. 本次范围边界

本次交付是管理与加工流程设计，没有新增管线执行、没有重建/删除用户数据、没有调用付费模型或修改闸门。既有审核工作台完成的局部编辑、版本/哈希和 loopback 安全保护继续保持。网络多人 Web 登录门户、自动训练、远程执行平台不顺带纳入本提案。

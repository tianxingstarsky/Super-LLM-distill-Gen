# 工作流运行适配

正文 CoT 补写只使用供应商返回的可见正文，原生推理保留为请求证据；不从空正文的原生通道取替代值。v3 额外传递程序确定的工具决策／文本回答时点，传输、流式日志、并发和检查点仍复用同一请求运行时。

`workflow.conversation_reasoning_hints` 与 `workflow.conversation_reasoning` 共用输入节点的冻结模型和调度，分别接收提示正文和解释正文，由程序装配 `reasoning_hints` / `reasoning_content`。v2 用两个独立消息上下文并记录独立检查点、原生通道和实际用量；补写请求不继承提炼请求。历史只到当前响应之前，不要求模型包装 JSON，也不以原生通道代替可见解释。v1 保持原有单请求路径。

`experience_evolution_model.py` 使用组合根注入的节点模型客户端，一次严格 `submit_experience_rules` 提案提交；上游完整响应、原生提炼思考和 usage 先持久化再做本地引用校验。缓存身份包含输入、模板、提交合同和模型配置，重复输入不重新购买已完成响应。它不调用独立评审，不自动应用候选；版本库保留父版、实际用户编辑与原始轨迹。

`ExperienceEvolutionRepository` 接收组合根提供的当前用户目录，以追加文件保存经验版本、原始轨迹、父版本及来源收据。完整落盘后原子发布，已有版本不可覆盖；读取核对正文摘要，路径只接受版本 ID。它不调用模型、不更新工作流缓存，也不把候选标记为评审通过。模型提案端口由组合根另行提供。

阅读情景路线的三类文本请求复用原生双通道传输、SDK、节点绑定与检查点；程序装配字段，不让模型包装 JSON。回答请求逐字使用应用层形成的 learner messages，不再注入私有来源或制作指令。固定的系统／资料前缀保持稳定，续聊只追加已发生的对话；缓存命中由上游实际 usage 证明，不承诺永久命中或无限上下文。验证：`test_reading_session.py`。

`native_cot_messages.py` 将原生生成的规则、允许范围内的知识及不具权威性的修订稿放入系统上下文，真实对话保持原角色。新配方的短执行状态置于稳定知识前缀之后，不进入 learner 消息或训练字段；缺少版本标记的任务保留原消息。`CheckpointedModelRequest` 通过既有 `ChatClient.chat` 流式接收同次 `reasoning_content` / `content`，程序装配字段；不调用 JSON 修复、严格提交工具、前缀续写或第二位作者。思考关闭时请求前拒绝；未返回推理则保留答案并隔离，不能拿答案冒充原生思考。验证：`test_native_joint_cot.py`。

保真改写版本 2 在直接请求和来源检索两条路径使用 `edit_authored_candidate`。原始工具参数、编辑基稿和作者会话一并落盘；恢复不重购已完成调用。SDK/端点/并发/流式传输仍复用现有运行时。仅程序组装正文，答案不进入可编辑字段。旧任务仍提交完整正文，不自动升级。

`authored_edit_adapter.py` 认证原作者请求，复用 `CheckpointedReasoningAgent` 的严格工具传输、并发限制、流式日志和检查点。模型、端点、账号、API 格式、推理配置或节点绑定改变时在编辑调用前拒绝切换；原请求只持久化整体身份摘要，不保存凭证明文。严格提交检查点新增可选 `author_session`，旧缓存不迁移，训练导出不受影响。消息前缀及工具声明是否一致、实际供应商 usage 分别记录；相同前缀是复用条件，不是命中承诺。编辑返回结构有效仍需原业务质量验证。

会话状态和工具调度继续由既有用例及认证检查点承接。未引入额外图执行器或第二个检查点库，原始扩展字典、工具失败和取消语义保留。

配方 39 在资料加载与消息投影前应用用户任务范围；只有明确限制到可见选段时才从该次请求排除教师全文、包引用和全文引用。资料原件和缓存不变。推理及原生答案两阶段均携带程序解析出的答案语言与范围，不能从双语推理猜测答案语言。核查与角色投影继续使用既有实现；验证见 `tests/test_authored_task_contract.py`。

配方 36 的 `authored_submission_version=1` 使用严格工具提交完整推理及证据结构，原生答案续写仍走原通道。完整工具响应先保存独立检查点，再由程序组装记录；本地字段失败恢复时不重新请求。普通节点与可选来源检索均接入同一合同，流式日志、使用量和原生思考保留。旧配方不迁移；只有新建且固定到官方 DeepSeek Chat 的生成中推敲任务自动启用。

配方 35 将显式配置的思考要点移动到真实对话和阶段合同之后的 system 消息，只放一份。原生答案续写仍仅接收 final 专用要点；资料前缀、真实历史和完整原生推理前缀不变。适配器读取冻结的用户规则，不擅自补默认规则。配方 34 及以前保持旧位置；验证见 `tests/test_reflection_guidance_placement.py`。

配方 34 的 `authored_stage_contract_version=1` 在完整真实对话之后追加当前撰写阶段的系统合同。`model_request_adapter.py` 保留资料前缀、实际用户原话、历史回答及原生推理前缀；旧配方不追加，新合同不进入训练导出。真实 SDK 与旧任务兼容验证见 `tests/test_authored_stage_contract.py`。

`generation_source_adapter.py` 复用原请求角色投影、冻结提示词、共享并发、流式记录和逐回合检查点，工具传输复用 `CheckpointedReasoningAgent.prepared_tool_turn`，不加入评审身份。`generation_source_search.py` 使用 SQLite FTS5/BM25 索引已认证资料范围，最多保留四份进程内索引；该缓存可重建，原资料和请求收据仍持久保存。关键词检索不等于语义向量检索；此版本不调用嵌入服务、不联网补资料、不认证生成质量。验证见 `tests/test_generation_source_lookup.py`。

配方 33 的生成中推敲通过 `structured_response_attempts=1` 关闭 JSON 失败后的整段重采样，原生答案续写同样只尝试一次。失败保留流式记录及已有推理；旧配方的重试和检查点不变。策略由生成用例决定，适配器只透传到模型端口。验证见 `tests/test_integrated_reflection.py`。

新配方 28 / 清单版本 6 固定 `workflow.cot_check_agent@1.4.0`，仍通过现有模型请求端口、共享并发限制、流式日志和检查点运行。旧配方 27 保持 1.3.0；已保存任务不自动升级。

配方 27 / 清单版本 5 固定 `workflow.cot_check_agent@1.3.0`，继续通过原模型端口、共享并发和可恢复原生工具会话执行。环境状态和工具顺序属于用例/领域层，适配器不增加第二套 Agent 循环。旧配方 26 的 1.2.0 提示词和检查点保留；两个配方均列入运行时支持版本。

版本 4 在 `CheckpointedReasoningAgent` 中显式开启完整 Chat 响应的坏参数反馈。原始参数、原生推理与恢复记录保留，错误参数不执行，后续回合仍经共享并发和检查点。旧版本合同不变，配方 26 冻结新核查模板。

`reasoning_agent_adapter.py` 将版本 3 核查会话接入 CoT 节点的冻结提示词、模型绑定、原生工具协议、全局模型并发/冷却控制及可恢复请求。它只做一次模型工具回合，不承接 Agent 决策循环。旁路流式记录与用量仍使用现有日志，全部工具回执保留在审核证据中；不向训练答案添加检查表。尚未以真实付费请求验证新调度的延迟或质量，不能把本地回放测试当作模型效果。

按需读取仍通过已有来源包加载与投影，认证缓存内容并遵守指导员选定的行范围。整份资料保留行号视图，选定范围保留对应原文；过期焦点文本和原始解析回执不混入核查来源。范围越界失败，不回退为整份资料。

`checklist_adapter.py` 将返工后的证据自检固定到 CoT 节点的模型与提示词。它不实现自检规则；调用仍复用原请求检查点与模型并发调度。

`driver.py` 的 `FilesystemWorkflowRunDriver` 处理对外运行端口。只读状态查询不会加载模型执行引擎。

`execution_runtime.py` 提供两个明确角色：

- `FilesystemRunSession`：运行锁、最新状态、快照核验、持久化结果、已过滤错误。
- `CheckpointedBatchRuntime`：输入记录、磁盘候选、单阶段执行、最终打包及完成事实。

生产失败保留明确的内部异常类型或业务错误码；只有已分类的模型请求错误才展示为服务故障。输入全部隔离的任务仍封存零产物报告，不补造指导员执行记录。回归见 `tests/test_director_delivery_audit.py`。

它们连接旧 `TrainingWorkflowRuntime`，不决定普通批次的阶段顺序。该顺序属于 application。存储文件格式、恢复检查点和部分交付策略必须兼容历史任务。

| 文件 | 责任 |
| --- | --- |
| `conversation_import.py` | 有界调用独立转换器、核对输入未变与输出收据、原子暂存和复用持久资料缓存 |
| `generation_adapter.py` | 已认证来源、节点请求、生成检查点和流式推理交付；不承接生成循环 |
| `model_request_adapter.py` | 冻结提示词、来源角色投影、模型绑定、流式日志、响应证据与检查点适配 |
| `dialogue_adapter.py` | 读取并验证来源记忆；复用已有请求调度、角色、流式输出和检查点 |
| `production_adapter.py` | 轮次会话、落盘、事务提交、部分结果与最终交付 |
| `production_storage.py` | SQLite 来源窗口、按收据选择的流式产物集合 |
| `production_batch.py` | 一个窗口的检查点节点执行与上游质量证据保存 |
| `production_runtime.py` | 旧运行时接入钩子、规划检查点、收据校验、去重索引和核验后对账 |

`production_runtime.py` 中的兼容方法把调度交给应用用例。不要向这里重新添加轮次主循环。`lib/infrastructure/workflow_production.py` 仅保留同一模块的导入别名。组合根向生产适配器注入数据集域的磁盘索引，适配器不直接导入邻域实现。

不要记录原始供应商异常，可能包含密钥或原文。不得因“已有检查点”跳过导出核验。验证包括工作流、取消、恢复、批量生成和凭据阻断测试。

`CheckpointedModelRequest` 的旧客户端和提示词钩子由 `bootstrap/workflow_requests.py` 注入，保留历史测试和调用方替换点。不要在适配器中重新加入 SFT/CoT 或请求重试循环。检查点键、端点身份、提示词版本、响应证据和原生推理字段都继续使用已有合同。

`ExternalConversationImporter` 不解释厂商事件格式。DSH 读取器位于 `plugins/dsh-dataforge`，核心只校验规范 JSONL 和版本化收据。临时输入与输出目录隔离，导入不执行记录中的工具或调用模型。`tests/test_conversation_import.py` 覆盖收据、篡改、重复导入、路径和文件名碰撞；`test_dsh_import_ingestion.py` 覆盖后续训练输入规则。

配方 29 对应显式 `evidence_policy=1`，冻结核查模板 1.5.0。资料原件认证只读取当前运行 inputs 快照并比较冻结 SHA-256，不相信传入的已认证标记。核查的稳定资料前缀与动态任务分离，复用供应商前缀缓存；完整收据使用现有原子检查点。旧配方 28 仍固定 1.4.0。

证据策略 2 仍通过当前模型端口及文件检查点运行；配方 30 冻结模板 1.6.0。引用与数量规则位于 domain，不在 SDK 适配层猜测单位或修补模型结论。

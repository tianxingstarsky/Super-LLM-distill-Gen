# 模型用例

`retry_port.py` 定义有限重试决策；三个请求用例经组合根使用 Tenacity。用例决定错误分类、费用结算与重试资格，通用尝试循环由依赖执行。程序异常、取消、坏工具结果不能进入盲重试。

`ExecuteToolTurn(strict=True)` 接收适配器的真实流式增量，完成后仍先结算实际使用量，再验证工具决策。观察器异常与取消不重试；严格通道失败保留原始诊断。默认旧通道保持整段响应事件语义，不执行工具。对应端口仍不依赖 SDK。

| 文件 | 责任 |
| --- | --- |
| `service.py` / `ports.py` | `BackendApplication` 的配置操作与读写端口 |
| `execute_request.py` | `ExecuteModelRequest` 的共享准入、限次重试、格式降级、取消传播和响应发布 |
| `request_json.py` | `RequestJSONResponse` 的 JSON 校验与有界重试；认证、网络和取消错误不在此重复重试 |
| `execute_tool_turn.py` | `ExecuteToolTurn` 的完整工具决策请求；仅返回工具调用，不执行工具 |
| `request_ports.py` | 文本、JSON、工具决策以及调度、结算和错误分类端口 |

用例只依赖领域和端口，不构造 SDK、不读写文件、不等待系统时钟。应用层决定何时获取与释放资源，适配器负责实际调度、网络和存储。调用方取消和观察器异常不得包装成可重试供应商错误；部分输出不能作为完整响应发布。

JSON 重试仅捕获明确的语法异常（`JSONResponseDecodeError` / 标准库 `JSONDecodeError`）。下一次请求携带上一份可见原始 JSON 与解析位置反馈，保留原有消息角色，不累积全部失败回合，也不把供应商隐藏推理当作 JSON。相同坏响应在反馈后再次出现即终止；保存收据失败、解析适配器程序异常不重复购买模型请求。原始响应日志和按次计费继续由基础设施维护。

格式能力拒绝沿用旧降级语义，不额外消耗用户的重试次数。已发送请求的未知费用、确定拒绝的释放、成功使用量与共享冷却时机保持原合同。JSON 结果只提交成功尝试的响应证据。工具响应先记真实使用量，再校验其内容，不把工具请求执行与工具执行混在一起。

工具响应被上游截断时，`ExecuteToolTurn` 将原始响应详情放在 `incomplete_response` 诊断中，并将可用的原生推理通知给观察器。随后仍抛出终止错误；不返回或执行部分工具调用，不发完成事件，也不自动重试。诊断不进入训练样本，不改变一次响应只结算一次的约定。

验证：`tests/test_model_request_use_cases.py` 使用内存端口覆盖排队、重试、取消、失败结算和结果发布；`tests/test_model_tool_calls.py` 用 Chat、Responses、Anthropic 的截断响应验证诊断保留、单次结算及无重试。模型协议、调度及流式回归验证实际适配器。
